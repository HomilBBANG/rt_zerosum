# 2D 미국 카툰 셀 셰이딩·극명한 원색 조명 구현서 v0.2

- 목적: **Godot 4.7 기반** 횡스크롤 전투와 군대 시설 관리 화면에서 재현할 수 있는 그래픽 스타일/제작 파이프라인 정의
- 성격: 사용자 확정 그래픽 방향을 반영한 **아트 구현서**. 셰이더·씬 노드·색상값·작업 순서 등은 모두 **[기술 제안/검증용]**이며, 그 자체가 본편 기획 확정은 아니다.
- 참조 이미지: **1~4번 = 건물/공간/조명 연출**; **5번 = 캐릭터 목표 그림체**. 앞서 제공된 푸른 하늘·코랄 톤의 참고 이미지도 **색감의 한 사례**로 보존한다.

## 1. [확정] 새 그래픽 스타일

| 요소 | 확정 의도 | 제작시 해석 |
|---|---|---|
| 조명 | **조명별로 쨍한 원색을 사용해 극명한 색채·명암 대비** | 빨강 대 초록, 분홍 대 청록, 보라 대 파랑, 코발트 대 주황 등 강한 색면의 분리. 모든 장면을 같은 파란 필터로 덮지 않음 |
| 배경/건물 | **낮은 세부 묘사, 단순한 셀 셰이딩** | 건물 구조는 읽히되 단순한 색면 중심, 면 경계가 분명한 명암 |
| 캐릭터 | **미국 카툰풍의 단순 셀 셰이딩** | 5번 레퍼런스의 선·형태 단순화, 표정 형태, 명암 구획, 애니메이션용 실루엣을 목표로 그림체 통일 |
| 전체 | **2D 게임 렌더링** | 2D 스프라이트/레이어/셰이더로 구현 가능한 파이프라인 우선 |

**규칙 구분:** 5번은 **화풍 레퍼런스**이며 그 이미지 속 특정 캐릭터의 얼굴·헤어·복장·체형을 모든 캐릭터에 강제하는 뜻이 아니다. 캐릭터 원형 설정은 별도 논의한다.

## 2. 레퍼런스별 조명·형태 분석

- **1번(청록 + 핑크)**: 보색에 가까운 넓은 조명 면이 공간을 분할. 사물은 많지만 재질 텍스처보다 조명 덩어리가 우선. **테스트 기준:** 실내의 청록 영역과 문밖의 핑크 영역이 한눈에 분리되는가.
- **2번(보라 + 남색/시안)**: 가구/벽의 형태는 짧은 직선과 큰 셀 형태로 유지, 조명색이 공간 전체의 인상을 결정. **테스트 기준:** 같은 소품에 조명만 바꿔도 다른 분위기를 만들 수 있는가.
- **3번(초록 + 강한 빨강)**: 넓은 녹색/초록 빛 바닥과 새빨간 안쪽 공간의 충돌, **날카로운 그림자 경계**. **테스트 기준:** 큰 명암과 색 덩어리가 세부 질감 없이도 초점을 만든다.
- **4번(파랑 + 주황)**: 차가운 남청 공간에 포화된 주황의 실내 빛이 커다란 폴리곤처럼 드리워짐. **테스트 기준:** 빛이 닿는 면의 경계를 흐리지 않고 단단한 모양으로 표현.
- **5번(캐릭터 그림체)**: 큰 눈과 정돈된 이목구비, 명확한 눈썹/윤곽, 형태가 읽히는 긴 실루엣, 머리/의상에 **적은 수의 큰 셀 명암 면**. 과도한 피부 텍스처·미세 반사광·복잡한 재질 표현은 목표와 다름. 모든 캐릭터의 비례를 5번 인물과 동일하게 할지는 **미정**.

## 3. 제작 공통 지침

### 3.1 [확정 목표] '적은 디테일, 높은 색 대비'

- 캐릭터/배경 모두 **선화와 평면색으로 형태를 구별**하고, **명암은 큰 덩어리 단위로 끊는다.**
- 조명을 비추는 영역과 그림자 영역은 가급적 **날카로운 경계**를 갖는다. 부드러운 그라디언트는 필요한 부가 효과에서만 [검증용]으로 사용한다.
- 화면 내 **색 대비는 장면마다 달라짐**. 특정 8색, 코발트·코랄 조합만 계속 강제하지 않는다.
- 채도가 높더라도 **캐릭터와 배경은 명도·실루엣으로 분리**한다. UI의 체력·AP·현재 행동 캐릭터 표시가 빛에 묻히지 않도록 한다.

### 3.2 [제안] 원화 규격

- 캐릭터: 투명 배경 스프라이트, 큰 실루엣, 얼굴/상의/하의/장비 등 중요한 형태별 색면을 분리해 제작.
- 건물: 원경/중경/전경 구성은 **검증용**. 캐릭터와 닿는 바닥, 벽, 문, 창 등 공간의 핵심 구조물부터 작업.
- 셀 단계: 기본색 + 큰 그림자 + 키 라이트/림라이트를 분리하는 2~4개 색 영역부터 시험. 단계 개수는 고정하지 않음.
- 선 굵기/텍스처: 심플한 미국 카툰 외곽선과 필요한 내부 선은 허용. 사진 텍스처/극세 묘사는 피함. 정확한 선 두께(px)는 원화 출력 크기 결정 후 실험.

## 4. Godot 4.7 구현 방식 (모두 [기술 제안])

### 경로 A: 가장 빠른 프로토타입 — '그림에 포함된 빛 영역 + 색상 교체 마스크'

가장 적은 개발 비용으로 스타일을 검증하는 방식. **셀 형태의 빛 영역을 원화 또는 별도 마스크로 직접 디자인**한다.

```text
원화 full-color RGBA Sprite2D
    + 같은 크기의 light_zone_mask.png (4개 명도 코드, 무손실)
    → ShaderMaterial(cel_zoned_lighting.gdshader)
    → 장면 별 그림자/환경광/키라이트/보조광 색 설정
    → UI는 별도 CanvasLayer로 유지
```

- 마스크 검정(0): 진한 그림자 / 회색(85): 기본 주변광 / 밝은 회색(170): 주조명 / 흰색(255): 대비 보조광. **마스크의 색 영역이 즉시 하드 에지 조명 형태가 된다.**
- 한 장면 내 한 스프라이트에 조명색을 **색상 유니폼**으로 교체할 수 있어, 똑같은 캐릭터가 청록/핑크 조명이나 남청/주황 조명을 받도록 테스트할 수 있다.
- 이 방법은 **자동으로 조명 방향에 맞춰 셀 경계가 변하는 실시간 광원 시뮬레이션이 아니다**. 캐릭터의 이동/회전에 따라 자연스럽게 그림자 형태까지 바꾸려면 별도 아트·마스크 갱신이나 경로 B를 검토한다.
- 색상 혼합이 캐릭터 고유색을 지나치게 없애면 `key_mix`/`accent_mix`를 낮춘다. 피부·눈·팀 구분은 유지되어야 한다.

**파일:** `cel_zoned_lighting.gdshader` (시연용; Godot 엔진 내 컴파일·표시 확인 전)

### 경로 B: 움직이는 조명을 검증 — Godot 2D Light2D + 후처리형 셀 분할

- `CanvasModulate`를 주변색 베이스로 쓰고, `PointLight2D` 또는 `DirectionalLight2D`로 색광을 준다.
- 건물 벽과 명확한 그림자가 필요한 오브젝트는 필요한 경우 `LightOccluder2D`를 검토한다.
- 2D 노멀 맵과 사용자 정의 `CanvasItem` 셰이더의 **빛 세기 임곗값 분할**을 실험하면 부드러운 광원을 단단한 셀 형태로 다듬을 수 있다. 단, 실제 구현 시 움직임·조명 겹침·일관성·성능을 확인해야 한다.
- **주의:** 일반적인 2D 조명을 그대로 추가하는 것만으로는 레퍼런스의 날카로운 빛 경계가 보장되지 않는다. 전경의 빛 윤곽은 아티스트가 만든 **폴리곤형 색면/마스크**가 더 정확하고 싸게 재현될 수 있다.
- 기술 경로 A와 B의 선택 및 혼용 여부는 **미확정**이며 화면 테스트 후 결정한다.

Godot 공식 참고: https://docs.godotengine.org/en/4.7/tutorials/shaders/shader_reference/canvas_item_shader.html 및 https://docs.godotengine.org/en/4.7/tutorials/2d/2d_lights_and_shadows.html

## 5. 기존 v0.1 팔레트 셰이더와 관계

- 예전 `indexed_palette.gdshader`는 **8색 고정 팔레트 인덱스 셰이더**였고, 최초 파랑/코랄 참고 이미지의 색상 실험용으로 보관한다.
- 지금 확정된 목표는 **조명마다 달라지는 강렬한 원색 대비**이므로 **8색 단일 팔레트를 캐릭터·배경 전체에 강제하는 접근은 기본안이 아니다.**
- 기존 파일을 덮어쓰지 않는다. 필요하면 과거 장면 시험에만 선택 적용하고, 신규 기본 시연은 `cel_zoned_lighting.gdshader` 또는 원화에 그린 하드 에지 라이트로 수행한다.

## 6. 먼저 확인할 그래픽 시연 화면 [검증용 제안]

| 시연 | 구성 | 검증 목표 |
|---|---|---|
| G1 | 동일 실내 배경 + 청록/핑크 조명 | 두 빛 영역 경계와 단순한 구조물이 자연스럽게 보이는가 |
| G2 | 동일 캐릭터 + 빨강/초록 조명 | 캐릭터의 얼굴·실루엣·기본색이 계속 식별되는가 |
| G3 | 동일 공간 + 남청/주황 라이트로 교체 | 그래픽 소스를 대량 재제작하지 않고 색 분위기를 바꿀 수 있는가 |
| G4 | 횡스크롤 전투 6인 + 적 진영 | 강한 조명 위에서도 현재 캐릭터·목표·HP·AP를 구별 가능한가 |
| G5 | 아웃게임 시설 내부 | 미국 카툰풍 구조물과 강렬한 조명이 관리 화면을 방해하지 않는가 |

> 조명 예시 색 조합은 레퍼런스 분석을 바탕으로 든 **테스트 장면**이지, 특정 장소나 스테이지의 확정 팔레트가 아니다.

## 7. 구현 시 주의사항

1. **스타일 재현은 셰이더만으로 해결되지 않는다.** 스프라이트의 외곽 형태·셀 그림자 면·조명 마스크를 사람이 디자인해야 한다.
2. **빛의 면을 무턱대고 블룸 처리하거나 전체 씬에 블루 필터를 걸지 않는다.** 목표는 '빛나는 발광 효과'보다 **뚜렷한 색 면의 대비**다.
3. 플레이어의 현재 행동 캐릭터, 대상 지정, AP UI에 원색 조명을 중첩해 정보 가독성을 떨어뜨리지 않는다.
4. 크기가 다른 화면에서 조명 경계가 흐려지거나 캐릭터 얼굴의 명암이 깨지지 않게 검증한다.
5. 영상/원화가 미확정인 상태에서 셰이더는 **시험용 도구**이며, 전체 그래픽 스타일의 완성도를 보장하지 않는다.

## 8. 향후 승인 필요한 아트 선택

- 스프라이트 프레임 애니메이션 / 본 애니메이션 / 혼합 중 어떤 것을 채택할지
- 5번 캐릭터의 **화풍만 차용**할지, 캐릭터의 공통 비례 규칙도 차용할지
- 전투/아웃게임 양쪽에 동일한 광원 스타일을 항상 강제할지, 장면 상황에 따라 강도를 변화시킬지
- 정적 빛 마스크와 실시간 Light2D 중 어느 것을 기본 구현 방식으로 확정할지
- 선 두께, 해상도, 원화 분할 규격, 각 장소의 실제 광원색 구체 수치

---

**결정 경계:** [확정]은 사용자 발언에서 직접 온 방향뿐이다. 노드, 팔레트, 스프라이트 레이어, 마스크 구획, 샘플 컬러, 셀 단계 수는 모두 **제안/검증용**이다.
