# 전쟁 게임 — 전투 플레이어블 프로토타입 기획서 v1.0

> 엔진: Godot 4.7 / 목적: 전투 재미 검증 / 상태: 승인된 핵심 규칙 + 구현용 임시값을 구분. 본 문서는 실제 게임 완성본이 아닌 개발 지시용 명세.

## 0. 현재 구현 반영 (변경될 때마다 갱신)
> 아래는 원 기획 이후 사용자 결정으로 바뀐 내용. 상세 결정 이력은 `00_decision_log_v1_0.md`, 아트 규격은 `../ui_art_spec.md`.
> 마지막 갱신: 2026-10-29 (하나 포즈 10장 — dead·point_up·stun·annoying·awkward 추가)

- **표현**: 캐릭터 2D **스프라이트 프레임 애니메이션**(**스프라이트 시트** `assets/characters/<id>/<동작>_<칸 수>.png`, 사용자가 제작 — 시트 없는 동작은 기본 그림 한 장. 현재: 하나·니키타·키라·단·이선·앨마 idle(기본 그림 숨쉬기) — 니키타(빨간 머리 의무병 코트)·키라(회색 군복, 최종)·하나(곱슬머리 군복·오른쪽 눈 아래 점, 최종)·앨마(흰 의무 가운)는 새 그림으로 교체되어 예전 걷기·피격·공격 시트는 지움) + 배경 3D(실광원·그림자). Skeleton2D 리그·3D 캐릭터 전환은 제거.
  칠 방식: **전 캐릭터 네온 칠**(선화는 원화 그대로, 면은 원화 밝기대로 조명색으로 덮음 — 어두운 면은 깊은 보라, 밝은 면은 조명색). `character.json` `"style": "classic"` 이면 예전 셀 칠, `"neon_gradient"` 0~1 = 몸 위→아래 색상 그라데이션(기본 끔).
  외곽 림(빛 반대쪽 가장자리 선): 그림 실루엣에서 셰이더가 직접 그림 — 원화 760px 기준 14px 두께, 윤곽을 따라 매끄럽게(계단 없음). 빛 반대쪽 가장자리 중 바깥이 트인 곳에만(턱 아래·밑단과 부츠 사이 같은 작은 틈 제외), 머리카락 끝 같은 가는 끝까지(림 안에선 어두운 먹선만 보존).
  눈(흰자·눈동자): 눈 마스크(`base_eye.png`)가 있으면 원본 색 그대로 — 아군 6인 전원 + 시험 캐릭터.
- **앨마 애니메이션**: idle · walk · run · attack · death — 사용자 AI 시트(6x6)에서 튀는 프레임·불필요 구간 빼고 반복 구간·속도 조정 (`tools/char_sprites.py report/sheet`). **단·이선·키라** idle · walk · run (사용자 AI 시트, 키라 idle 은 왕복 재생). **하나·니키타** idle = 원화 리깅(숨쉬기·머리·팔, 눈 깜빡임 없음), walk · run = AI 시트를 4배 확대(해상도 유지)하고 원화 머리를 붙임. **로한** idle = 리깅.
- **스프라이트 시트 내보내기**: `tools/char_sprites.py export <캐릭터>` → `exports/sheets/<캐릭터>/<동작>_sheet.png` + json (모든 동작 같은 칸·같은 발 위치, 원본 해상도). 니키타 idle·walk·run 내보냄. `rows` = 동작마다 한 줄인 긴 시트(1줄 idle · 2~3줄 걷기 오른쪽/왼쪽 · 4~5줄 뛰기 오른쪽/왼쪽, 왼쪽 = 좌우 뒤집기). 게임은 여전히 동작 폴더 프레임을 씀.
- **세계관 도감**: 기지 상단 `도감` · 신 아이콘 클릭. 탭 = 등장인물 · 몬스터 · 상태이상 · 종교(신) · 도시 배경 (`data/codex.json`, 게임 데이터 항목은 자동 + 설명만 덧붙임). [임시] 설명 전부.
- **신 해금 캐릭터 · 기적**: 정체가 신인 캐릭터 — 해금 조건(직접 / 미션 완료(의뢰·전투·연구·퀘스트) / 레벨 / 신앙도 / 친밀도 / n일차, 또는 처음부터 해금)을 채우면 신앙 탭이 '기적'. **기적은 신앙이 아니라 의지로 배움** — 해금될 때 시작 의지(에디터 `시작 의지`), 출전마다 + `will_battle`(기본 5), 신앙도는 기적에 안 씀. 에디터 `기적 (신 해금)`에서 캐릭터·신·조건·시작 의지·기적(필요 의지) 설정. **하나 = 신, 잠김 — 퀘스트 '하나의 비밀' 완료로 해금** ([임시] 정체 테라 · 시작 의지 10). 니키타는 신 아님.
- **컷씬**: 대화 장면(대원이 좌우에 서서 대사) · 이미지 CG · 배경 · 선택지 · 행동(퀘스트 시작·신 정체 해금·친밀도·현금). 컷씬 끝 → 다음 컷씬, 선택지 → 고른 컷씬으로 **이어짐**. 계기: 새 게임(오프닝) · 퀘스트 시작/단계/완료 · 대원에게 말 걸기 · 대원끼리 대화 엿듣기 · n일차 · 신 정체 해금 · 전투 승리 · 없음(이어지기 전용). 재생 중 시간 멈춤, Esc = 건너뛰기(행동은 적용). `data/cutscenes.json` + `assets/cg/` — **Godot 에디터 `컷씬` 탭**(목록 · 계기 · 컷 카드 · 게임과 같은 미리보기 · 흐름 · 검사 · 테스트 플레이). 본 컷씬 = 퀘스트 단계 '컷씬 보기' · 미션 `cutscene:id`. [임시] 9개 · 그림 4장.
- **퀘스트**: 기지 상단 `퀘스트` 창. 시작 조건(처음부터 / 직접 `start_quest` / 미션 완료 후 / 의뢰인 레벨·신앙도·친밀도 / n일차) → 단계를 앞에서부터 하나씩(의뢰 완료 · 전투 승리 · 대원과 대화 · 연구 · 친밀도 · 레벨 · 일차 · 다른 퀘스트, 횟수 단계는 그 단계 시작 뒤부터 셈) → 완료 보상(현금은 주간 결산, 의뢰인 친밀도). `data/quests.json` — **Godot 에디터 `퀘스트` 탭**(목록 · 시작 조건 · 단계 카드 · 보상 · 미리보기 · 신 해금 연결 · 검사 · 테스트 플레이). [임시] 하나의 비밀(호위 의뢰 → 전투 승리 → 하나와 대화 → 하나 정체 해금) · 로한의 첫 연구(2일차~).
- **신앙도 얻기**: 전투 출전으로는 안 오름 → 퀘스트 보상(신앙도 + 받는 대원) · 컷씬 행동(대원 신앙도 +/-) · 요청 수락(수락효과 `신앙:n`). **무신앙**(믿는 신 없음) 대원: 신앙 탭 "믿음이 없습니다.", 신앙 스킬 없음, 신앙도 안 쌓임.
- **믿는 신**: 에디터 `신앙 스킬` 화면의 `대원 신앙`(faith.json believers)에서 설정 — 엑셀 캐릭터 시트 신·신앙 열은 없앰. 신 아이콘 = 상징색 원 + 글자.
- **효과음**: 캐릭터별 발자국(걷기·뛰기, 아군 6명 모두) — 애니메이션의 발 닿는 프레임마다 한 걸음, 전투 자리 이동은 두 걸음. 쓰러짐(dead)은 공용(아군·몬스터).
- **무기 그림**: 손에 붙이는 무기 그림은 숨김. 전투는 다키스트 던전처럼 (무기까지 그린) 멈춘 그림으로 보여줄 예정.
- **카메라**: 뒤로 물러나 40° 내려다보는 원근, 전투 내내 전체 구도 고정(차례 줌 없음). `battle_2d.tscn` → View 노드 인스펙터에서 각도·거리·화각·바라보는 점·화면 위치 조절.
- **편성 (최대 6대2)**: 기본 편성 = 사람 캐릭터 6인 — 전방 단·키라 / 중앙 이선·하나 / 후방 앨마·니키타. 1~6명 출정 가능.
- **연구원 로한 (기지 전용)**: 전투에 나가지 않는 대원(출정 대기 목록에 없음). 지하 1층 서쪽 끝 **연구실**에서 일하고 연구실 간이침대에서 잠. **로한 클릭 → 무기 연구 창**.
  연구(엑셀 `연구` 시트): 비용($, 시작할 때) · 시간 · 선행 연구. 한 번에 하나, 로한이 연구실에서 깨어 있을 때만 진행. 완료 → 그 무기를 무기고에서 **제작** 가능(연구 전엔 '잠김').
  [임시] 산탄총·기관단총·고주파 블레이드 → (기관단총 다음) 경기관총, (산탄총 다음) 유탄발사기. 수치·비용 더미.
- **레벨·스킬**: 전투 출전 → 경험치(승리 100 / 패배 40) → 레벨 업마다 스킬 포인트 +1(처음 1). 기지 `스킬` 버튼·대원 우클릭으로 **스킬 창**: 왼쪽 = 대원 목록(위아래 스크롤, 대원이 늘어나도 그대로), 위 탭 = **액티브 · 패시브 · 신앙** 스킬.
  **액티브**(전투 스킬 강화 · 새 스킬) · **패시브**(능력치) 트리. **모양은 캐릭터마다 자유**(격자 칸 위치 + 선행 선): 시작 노드는 처음부터, 선행을 배워야 다음(하나라도 / 모두), 같은 택일 그룹은 트리마다 하나. 지금 기본 데이터는 모두 십자형(중앙 + 화력·기동·생존·전술 3단계, 갈래 끝 = 택일). 스킬 포인트는 두 트리 공용. 레벨 미달 = 회색 + 붉은 "경험 부족".
  효과는 기지에서 출전한 전투에만(복제본). **노드는 `data/skill_tree.json` — Godot 에디터 `스킬 트리` 탭에서 직접 짬**(빈 칸 클릭 = 새 노드 · 끌어 옮기기 · Shift+클릭 선 잇기 · 모양 틀 5종 · 갈래 색 · 시작 노드 · 선행 · 택일 그룹, 이름·필요 레벨·효과·값·설명, 다른 캐릭터 트리 모양째 가져오기, 검사, 테스트 플레이). 새 스킬은 지금 액티브 갈래 끝에서만(기본 스킬 칸 3개). [임시] 수치·필요 레벨(시작 +0/+2/+4)·무료 초기화.
- **상황별 포즈 그림**: 캐릭터별 한 장 그림 — 하나 10장(hit · miss · shot 저격총 · slash 대검 · tired · dead · point_up · stun · annoying · awkward 대화용) · 니키타 8장: shot(공격) · point_up(버프·스킬) · hit(피격) · miss(회피) · stun(기절) · tired(디버프·구속·AP 다 씀=탈진) · dead(쓰러짐, 회색 처리 없음) · annoying(패배 결과 화면). 쓰는 쪽 포즈는 스킬마다 에디터 `스킬 포즈`(data/skill_poses.json, 자동 = 적 대상 피해·상태 shot — 근접 무기면 slash / 그 밖 point_up). 잠깐 바꾸는 포즈는 가운데 기준 20% 빠르게 확대 + x −5(뒤쪽)에서 1.5초 동안 가운데로 → 원래 크기 · idle, 카메라 고정, shot·hit 때 처음 0.2초 카메라 흔들림. 컷씬 대사 컷마다 포즈 고르기. 연출 값은 View 인스펙터 `포즈 연출`. [임시] 수치 · 탈진 = AP 0 해석.
- **신 아이콘 그림**: 신마다 아이콘 그림(assets/gods/) — 있으면 글자 대신. 에디터 신앙 스킬 화면 `아이콘 그림` · `그림 가져오기…`.
- **명중 · 회피**: 적에게 쓰는 피해·상태 이상 스킬만 판정. 명중률 = 스킬 명중 + 쓰는 캐릭터 명중 − 대상 회피 (5~100%, 100% 면 안 굴림). 빗나감 = 피해·상태 이상 없음(AP 는 씀), `빗나감` 표시 + 피하는 동작. 기절·구속 대상은 회피 0. 대상 고를 때 적마다 `명중 n%`. 엑셀 캐릭터·몬스터 `명중`·`회피` 열, 스킬 `명중` 열(빈칸 = 피해 90 · 상태 이상 85), 몬스터 스킬 에디터 `명중`, 스킬 트리·신앙 효과 명중·회피. [임시] 모든 수치.
- **전투 상태 이상**: 출혈(최대 HP v%/차례) · 화상(화염 고정 v, 방어 무시) · 동상(차례 n번 뒤 최대 HP v% 1회 후 해제) · 감속/가속(속도 v%) · 기절(n턴 행동 불가, 다른 아군이 기절한 캐릭터와 자리 교환은 가능) · 구속(n턴 이동·교환 불가) · 실명(n턴 대상 무작위: 아군 대상 → 아군 중, 적 대상 → 적 중).
  넉백(맞으면 v칸 뒤로, 같은 편과 자리 바꿈) · 끌어당김(v칸 앞으로) · 표식(n턴 이 대상 노리는 공격 위력 v%↑, 적 AI 우선 대상) · 도발(n턴 상대 편은 닿으면 이 캐릭터만 공격) · 취약(n턴 받는 피해 v%↑, 상태 이상 피해 포함) · 재생(걸릴 때·차례마다 최대 HP v% 회복) · 보호막(피해 v 대신 막고 사라짐, 최대 n턴).
  **상태 = 이름 + 효과 id** (`data/statuses.json`, 에디터 `상태 정의`): 같은 효과를 이름만 다르게 — 예: regen 재생 · regen_2 진통제 · regen_3 자가 치유. 규칙은 효과로만 판단.
  **상태 id = 효과 id, 같은 효과 두 번째부터 `_2`, `_3`**. 같은 id 는 겹치지 않음(다시 걸리면 갱신), id 가 다르면 같은 효과라도 따로 걸림.
  적용 = 처음 걸릴 때 한 번 + 그 캐릭터 차례마다 행동보다 먼저. n턴 = 그 캐릭터 차례 n번(차례 끝에 1 감소, 동상은 차례 시작에 감소). **스킬에 다는 곳 = 에디터 `스킬 트리` 탭 → `상태 이상` (`data/skill_status.json`)**, 한 스킬에 여러 개(각각 확률). 전투가 끝나면 사라짐. [임시] 어느 스킬에 무엇을 달지·수치.
- **신앙 스킬** (스킬 창 신앙 탭): 캐릭터마다 믿는 신, 신에 따라 배울 수 있는 신앙 스킬이 다름. 신앙도(0~100) ≥ 필요신앙이면 포인트 없이 배움(미달 = 회색 + 붉은 "신앙 부족"), 출전마다 +5.

## 1. 범위 및 완료 기준
- 플레이 가능한 1개 전투 씬, 편성 화면, 결과 화면. 최소 3회 연속 전투 재시작 가능.
- 전방/중앙/후방 각 2슬롯(최대 6인). 아군 6인과 적군 3~6인 테스트 데이터.
- 수동 전투만 개발. 자동 전투 AI(아군)는 알파 이후.
- 전투에서 스킬 선택, 대상 지정, 위치 이동/교환, 무기 변경, AP 보존, 턴 종료, 승패까지 정상 동작.
- 로그와 디버그 패널로 AP, 행동 순서, 피해, 대상, 위치 추적.
- 메인 스토리·캐릭터 수집·연출 완성도는 이번 검증 범위에서 제외. 군사 시설 경영(기지)·육성·세이브는 아웃게임 프로토타입(`outgame/`)으로 별도 구현 (2026-10-26).

## 2. 확정 규칙
### 2.1 편성
- 아군 전방/중앙/후방 각 2슬롯. 최대 6인 편성.
- 자신의 행동 차례인 캐릭터만 이동 명령 가능. 목표 슬롯이 비었으면 이동, 점유되었으면 그 아군과 자리 교환.
### 2.2 선공과 행동 순서
- 전투 시작 시 매복/기습 진영이 반드시 선공. 일반 전투는 동전 앞뒤로 선공 결정.
- 1라운드: 선공 진영 최고 속도 캐릭터 1명 우선 행동, 이후 양 진영 잔여 캐릭터 속도 내림차순.
- 2라운드 이후: 선공 특례 없이 전체 속도 내림차순.
- 속도 동률에서 아군 우선. 아군끼리 동률이면 높은 레벨 우선, 그것도 같으면 원거리 우선.
### 2.3 수동 전투와 AP
- 아군 캐릭터 차례에 일시정지하고 플레이어가 스킬과 대상을 직접 지정. AP가 남으면 한 턴에 여러 행동 가능.
- 모든 행동은 AP 소모(공격, 스킬, 위치 이동/교환, 무기 변경). 무기 변경은 AP 1 확정.
- 캐릭터별 최대 AP, AP 회복력 존재. 전투 시작 시 최대 AP 보유.
- 자기 차례 시작 시 AP = min(현재 AP + AP 회복력, 최대 AP).
- AP 0이면 자동 턴 종료. 남은 AP가 있으면 플레이어가 턴 종료 가능, AP 이월.
- 캐릭터별 구체 수치는 시스템 완성 이후 밸런싱. 지금은 임시 테스트 데이터만 사용.

## 3. 프로토타입 임시 규칙 (확정 아님)
- 공격/스킬 사용 AP 비용: 기본 공격 1, 강공격 2, 지원 스킬 2, 필살기 4. 이동 및 자리 교체 AP 1. 필살기 별도 게이지는 구현하지 않고 AP만 사용.
- 아군 6인, 적군 6인; 전투 시작 AP = 각자의 최대 AP (테스트: 5~8), 회복력 2~3, 속도 5~12, HP 20~40. 레벨과 원거리 여부는 동률 정렬 테스트용.
- AP가 부족한 행동은 비활성화. AP가 남아도 유효 행동이 없으면 턴 종료 버튼 제공. AP 0이 된 순간 현재 캐릭터 턴 종료.
- 적 AI는 자신의 차례에 AP로 가능한 행동을 최대 2회까지 실행하고 종료(전투 템포 검증용). 플레이어의 수동 입력 중 적 AI는 대기.
- 전투 내 라운드 시작에 살아 있는 캐릭터들의 행동 큐 생성. 사망 캐릭터는 큐에서 건너뜀. 속도 변화가 생기면 다음 라운드부터 순서에 반영.
- 동일 진영·동일 속도·동일 레벨·동일 사거리 등 모든 우선순위가 같은 경우 슬롯 순서 → 고정 인스턴스 ID로 결정. 적군끼리 속도 동률인 경우도 슬롯 순서 → ID 사용.
- 위치 제한의 첫 버전: 기본 근접 공격은 상대 전방 우선, 원거리는 어느 열이나 지정 가능. 전방 적이 없으면 다음 열 공격 가능. 지원 스킬은 아군 전 열 가능.
- 교환은 명령을 내린 캐릭터 AP만 1 소모하고 상대 AP는 소모하지 않음. 교환 자체로 턴을 강제 종료하지 않음.
- 승리: 모든 적 전투 불능 / 패배: 모든 아군 전투 불능. 전투 도중 부활/증원 없음.
- 전투 시뮬레이션은 난수 시드 고정 모드 지원. 매복/기습 여부는 디버그 메뉴에서 선택, 일반 전투는 동전 연출 후 선공 결정.

## 4. 전투 상태 머신
`PREPARE → INITIATIVE → ROUND_START → ACTOR_START → (PLAYER_COMMAND 또는 ENEMY_AI) → ACTION_RESOLVE → ACTOR_CONTINUE 또는 ACTOR_END → NEXT_ACTOR → ROUND_END → ROUND_START → RESULT`
- PREPARE: 편성 및 무기/스킬 확인, 시작.
- INITIATIVE: 최초 1회 선공 결정.
- ROUND_START: 행동 순서 계산, 첫 라운드 선공 예외 적용.
- ACTOR_START: AP 회복 후 행동 가능한지 확인.
- PLAYER_COMMAND: 행동 버튼 선택 → 유효 대상/슬롯 강조 → 확정 → AP 지불 → 행동 해결 → 다시 명령 대기(또는 턴 종료).
- ENEMY_AI: 동일 행동 API 호출.
- RESULT: 승패 및 요약, 재시작.
- 중복 클릭 방지, 애니메이션 중 입력 잠금, 취소 시 AP 미소모, AP 부족 시 거절.

## 5. UI 배치
> 현재 배치는 0절 참고 (상단 행동 순서 초상화, 발밑 체력·AP 칸, 하단 슬롯 줄). 아래는 원 기획.
- 16:9 기준 횡스크롤 전장. 좌측 아군 3열×2 슬롯, 우측 적군(임시 3열×2).
- 상단: 라운드, 선공 결과, 행동 순서 타임라인.
- 캐릭터 위: HP와 현재 AP/최대 AP, 현재 행동자 하이라이트.
- 하단: 현재 캐릭터 초상화, 스킬 버튼(비용 표시), 무기 변경, 위치 변경, 턴 종료.
- 이동 클릭 시 빈 슬롯은 이동 마커, 점유 슬롯은 교환 아이콘. 행동 확정 전 취소 가능.
- 적/아군 대상 클릭 시 유효 대상만 선택 가능. 선택 불가능한 이유를 툴팁에 표시.
- 디버그 패널: 속도·레벨·AP·HP, 라운드, 행동 큐, 시드, 매복 진영, 로그.

## 6. 그래픽 구현 가이드
- 2D 미국 카툰풍. 사용자 5번 캐릭터 이미지의 비율/얼굴 스타일을 목표로 삼되 임의로 동일 캐릭터를 확정하지 않음.
- 단순한 셀 셰이딩, 적은 텍스처 디테일, 실루엣과 큰 명암 면으로 형태 표현.
- 배경은 사용자 제공 1~4번 조명 레퍼런스: 광원별 선명한 원색(청/자/청록/분홍/주황/적 등)과 극단적 색상 대비. 특정 단일 팔레트 강제하지 않음.
- Godot CanvasItem 기반 캐릭터/배경 분리, 팔레트 마스크 또는 영역 마스크를 이용한 2~3단계 색상/명암 셰이더. 레이어별 광원 마스크를 통해 각기 다른 색상의 라이트 영역 구현.
- 프로토타입에서는 기존 레퍼런스 이미지를 게임 에셋으로 직접 배포하지 않고, 임시 도형/실루엣 및 독립 제작 스프라이트 사용.
- 색 변화는 광원 영역별로 독립 적용; 인물의 피부·의상 식별은 유지. 텍스처 필터와 경계 아티팩트 테스트.

## 8. 개발 순서와 테스트
1. 6슬롯 편성 및 전투 진입 → 슬롯 데이터 정확성.
2. 선공 판정, 1라운드 특례, 2라운드부터 속도순, 동률 정렬 단위 테스트.
3. 캐릭터별 AP 초기화/회복/최대치/이월, 다중 행동, AP 0 자동 종료.
4. 수동 스킬/대상 지정, 피해/회복, 행동 실패와 취소 처리.
5. 이동/교환, AP 1 소모, 무기 변경 AP 1, 턴 내 반복 행동.
6. 적 AI, 승패, 재시작, 행동 로그.
7. 셀 셰이딩 및 원색 대비 조명 적용, 전투 가독성 검증.

### 필수 검증 사례
- 적군 선공이지만 아군이 더 빠른 경우: 적 최고속 1명 → 나머지 전체 속도순.
- 2라운드에 선공 보너스 미적용.
- 동률 아군 우선 / 아군 레벨 우선 / 원거리 우선.
- AP 최대치에서 회복량 버림; AP 잔여 이월; 연속 스킬 후 AP 0 즉시 턴 종료.
- 이동 빈 슬롯, 점유 슬롯 교환; 현재 턴 아닌 아군 직접 이동 불가.
- AP 부족 행동·무효 대상 클릭 시 AP 소모 없음.
- 전투 종료 후 다시 시작할 때 AP, HP, 슬롯, 큐 모두 초기화.

## 9. 재미 검증 질문
- 전방/중앙/후방 배치가 실제로 타깃 선택과 위험 관리에 영향을 주는가?
- AP를 한 번에 소모하는 것과 남겨두는 것 사이에 선택 가치가 있는가?
- 행동 순서와 기습 선공이 전투 판단을 바꾸는가?
- 위치 교환과 무기 변경이 단순 클릭 낭비가 아니라 유의미한 전략인가?
- 6인 수동 조작이 지나치게 느리거나 번거롭지 않은가?

## 10. 의도적으로 확정하지 않는 사항
- 최종 캐릭터 스탯·스킬 비용·피해 계수·적 AI 전략·전열 효과·클래스·상성·상태이상(현재 프로토타입 2종만)·필살기 별도 자원·수집/육성/군사시설 경영 세부 규칙.
- 위 3절 임시 규칙은 구현 편의를 위한 교체 가능한 값이며 정식 게임 디자인 확정이 아님.
