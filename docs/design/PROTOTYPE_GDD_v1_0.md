# 전쟁 게임 — 전투 플레이어블 프로토타입 기획서 v1.0

> 엔진: Godot 4.7 / 목적: 전투 재미 검증 / 상태: 승인된 핵심 규칙 + 구현용 임시값을 구분. 본 문서는 실제 게임 완성본이 아닌 개발 지시용 명세.

## 1. 범위 및 완료 기준
- 플레이 가능한 1개 전투 씬, 편성 화면, 결과 화면. 최소 3회 연속 전투 재시작 가능.
- 전방/중앙/후방 각 2슬롯(최대 6인). 아군 6인과 적군 3~6인 테스트 데이터.
- 수동 전투만 개발. 자동 전투 AI(아군)는 알파 이후.
- 전투에서 스킬 선택, 대상 지정, 위치 이동/교환, 무기 변경, AP 보존, 턴 종료, 승패까지 정상 동작.
- 로그와 디버그 패널로 AP, 행동 순서, 피해, 대상, 위치 추적.
- 메인 스토리·군사 시설 경영·캐릭터 수집/육성·세이브·연출 완성도는 이번 검증 범위에서 제외. 추후 확장용 인터페이스만 고려.

## 2. 확정 규칙
### 2.1 편성
- 아군 전방/중앙/후방 각 2슬롯. 최대 6인 편성.
- 자신의 행동 차례인 캐릭터만 이동 명령 가능. 목표 슬롯이 비었으면 이동, 점유되었으면 그 아군과 자리 교환.
### 2.2 선공과 행동 순서
- 전투 시작 시 매복/기습 진영이 반드시 선공. 일반 전투는 동전 앞뒤로 선공 결정.
- 1라운드: 선공 진영 최고 속도 캐릭터 1명 우선 행동, 이후 양 진영 잔여 캐릭터 속도 내림차순.
- 2라운드 이후: 선공 특례 없이 전체 속도 내림차순.
- 속도 동률에서 아군 우선. 아군끼리 동률이면 높은 레벨 우선, 그것도 같으면 원거리 우선.
### 2.3 수동 전투와 AP
- 아군 캐릭터 차례에 일시정지하고 플레이어가 스킬과 대상을 직접 지정. AP가 남으면 한 턴에 여러 행동 가능.
- 모든 행동은 AP 소모(공격, 스킬, 위치 이동/교환, 무기 변경). 무기 변경은 AP 1 확정.
- 캐릭터별 최대 AP, AP 회복력 존재. 전투 시작 시 최대 AP 보유.
- 자기 차례 시작 시 AP = min(현재 AP + AP 회복력, 최대 AP).
- AP 0이면 자동 턴 종료. 남은 AP가 있으면 플레이어가 턴 종료 가능, AP 이월.
- 캐릭터별 구체 수치는 시스템 완성 이후 밸런싱. 지금은 임시 테스트 데이터만 사용.

## 3. 프로토타입 임시 규칙 (확정 아님)
- 공격/스킬 사용 AP 비용: 기본 공격 1, 강공격 2, 지원 스킬 2, 필살기 4. 이동 및 자리 교체 AP 1. 필살기 별도 게이지는 구현하지 않고 AP만 사용.
- 아군 6인, 적군 6인; 전투 시작 AP = 각자의 최대 AP (테스트: 5~8), 회복력 2~3, 속도 5~12, HP 20~40. 레벨과 원거리 여부는 동률 정렬 테스트용.
- AP가 부족한 행동은 비활성화. AP가 남아도 유효 행동이 없으면 턴 종료 버튼 제공. AP 0이 된 순간 현재 캐릭터 턴 종료.
- 적 AI는 자신의 차례에 AP로 가능한 행동을 최대 2회까지 실행하고 종료(전투 템포 검증용). 플레이어의 수동 입력 중 적 AI는 대기.
- 전투 내 라운드 시작에 살아 있는 캐릭터들의 행동 큐 생성. 사망 캐릭터는 큐에서 건너뜀. 속도 변화가 생기면 다음 라운드부터 순서에 반영.
- 동일 진영·동일 속도·동일 레벨·동일 사거리 등 모든 우선순위가 같은 경우 슬롯 순서 → 고정 인스턴스 ID로 결정. 적군끼리 속도 동률인 경우도 슬롯 순서 → ID 사용.
- 위치 제한의 첫 버전: 기본 근접 공격은 상대 전방 우선, 원거리는 어느 열이나 지정 가능. 전방 적이 없으면 다음 열 공격 가능. 지원 스킬은 아군 전 열 가능.
- 교환은 명령을 내린 캐릭터 AP만 1 소모하고 상대 AP는 소모하지 않음. 교환 자체로 턴을 강제 종료하지 않음.
- 승리: 모든 적 전투 불능 / 패배: 모든 아군 전투 불능. 전투 도중 부활/증원 없음.
- 전투 시뮬레이션은 난수 시드 고정 모드 지원. 매복/기습 여부는 디버그 메뉴에서 선택, 일반 전투는 동전 연출 후 선공 결정.

## 4. 전투 상태 머신
`PREPARE → INITIATIVE → ROUND_START → ACTOR_START → (PLAYER_COMMAND 또는 ENEMY_AI) → ACTION_RESOLVE → ACTOR_CONTINUE 또는 ACTOR_END → NEXT_ACTOR → ROUND_END → ROUND_START → RESULT`
- PREPARE: 편성 및 무기/스킬 확인, 시작.
- INITIATIVE: 최초 1회 선공 결정.
- ROUND_START: 행동 순서 계산, 첫 라운드 선공 예외 적용.
- ACTOR_START: AP 회복 후 행동 가능한지 확인.
- PLAYER_COMMAND: 행동 버튼 선택 → 유효 대상/슬롯 강조 → 확정 → AP 지불 → 행동 해결 → 다시 명령 대기(또는 턴 종료).
- ENEMY_AI: 동일 행동 API 호출.
- RESULT: 승패 및 요약, 재시작.
- 중복 클릭 방지, 애니메이션 중 입력 잠금, 취소 시 AP 미소모, AP 부족 시 거절.

## 5. UI 배치
- 16:9 기준 횡스크롤 전장. 좌측 아군 3열×2 슬롯, 우측 적군(임시 3열×2).
- 상단: 라운드, 선공 결과, 행동 순서 타임라인.
- 캐릭터 위: HP와 현재 AP/최대 AP, 현재 행동자 하이라이트.
- 하단: 현재 캐릭터 초상화, 스킬 버튼(비용 표시), 무기 변경, 위치 변경, 턴 종료.
- 이동 클릭 시 빈 슬롯은 이동 마커, 점유 슬롯은 교환 아이콘. 행동 확정 전 취소 가능.
- 적/아군 대상 클릭 시 유효 대상만 선택 가능. 선택 불가능한 이유를 툴팁에 표시.
- 디버그 패널: 속도·레벨·AP·HP, 라운드, 행동 큐, 시드, 매복 진영, 로그.

## 6. 그래픽 구현 가이드
- 2D 미국 카툰풍. 사용자 5번 캐릭터 이미지의 비율/얼굴 스타일을 목표로 삼되 임의로 동일 캐릭터를 확정하지 않음.
- 단순한 셀 셰이딩, 적은 텍스처 디테일, 실루엣과 큰 명암 면으로 형태 표현.
- 배경은 사용자 제공 1~4번 조명 레퍼런스: 광원별 선명한 원색(청/자/청록/분홍/주황/적 등)과 극단적 색상 대비. 특정 단일 팔레트 강제하지 않음.
- Godot CanvasItem 기반 캐릭터/배경 분리, 팔레트 마스크 또는 영역 마스크를 이용한 2~3단계 색상/명암 셰이더. 레이어별 광원 마스크를 통해 각기 다른 색상의 라이트 영역 구현.
- 프로토타입에서는 기존 레퍼런스 이미지를 게임 에셋으로 직접 배포하지 않고, 임시 도형/실루엣 및 독립 제작 스프라이트 사용.
- 색 변화는 광원 영역별로 독립 적용; 인물의 피부·의상 식별은 유지. 텍스처 필터와 경계 아티팩트 테스트.

## 7. Godot 폴더/데이터 구조 제안
```
res://
  scenes/formation.tscn
  scenes/battle.tscn
  scenes/result.tscn
  scripts/battle/battle_controller.gd
  scripts/battle/turn_scheduler.gd
  scripts/battle/ap_component.gd
  scripts/battle/action_resolver.gd
  scripts/battle/target_validator.gd
  scripts/battle/slot_manager.gd
  scripts/battle/enemy_ai.gd
  scripts/ui/battle_hud.gd
  data/units/*.tres
  data/actions/*.tres
  shaders/cel_zoned_lighting.gdshader
```
- `UnitData`: id, team, level, speed, range_type, max_hp, max_ap, ap_recovery, skill_ids, weapon_ids.
- `UnitRuntime`: current_hp, current_ap, slot, alive, equipped_weapon.
- `ActionData`: id, kind, ap_cost, target_rule, effect_payload.
- 행동은 모두 공통 `can_execute → pay_ap → resolve → emit_event` 경로로 처리. 스킬별 로직을 UI에 하드코딩하지 않음.
- 슬롯은 `(team, row, index)` 키 사용. 교환 시 양쪽 슬롯 참조를 원자적으로 갱신.

## 8. 개발 순서와 테스트
1. 6슬롯 편성 및 전투 진입 → 슬롯 데이터 정확성.
2. 선공 판정, 1라운드 특례, 2라운드부터 속도순, 동률 정렬 단위 테스트.
3. 캐릭터별 AP 초기화/회복/최대치/이월, 다중 행동, AP 0 자동 종료.
4. 수동 스킬/대상 지정, 피해/회복, 행동 실패와 취소 처리.
5. 이동/교환, AP 1 소모, 무기 변경 AP 1, 턴 내 반복 행동.
6. 적 AI, 승패, 재시작, 행동 로그.
7. 셀 셰이딩 및 원색 대비 조명 적용, 전투 가독성 검증.

### 필수 검증 사례
- 적군 선공이지만 아군이 더 빠른 경우: 적 최고속 1명 → 나머지 전체 속도순.
- 2라운드에 선공 보너스 미적용.
- 동률 아군 우선 / 아군 레벨 우선 / 원거리 우선.
- AP 최대치에서 회복량 버림; AP 잔여 이월; 연속 스킬 후 AP 0 즉시 턴 종료.
- 이동 빈 슬롯, 점유 슬롯 교환; 현재 턴 아닌 아군 직접 이동 불가.
- AP 부족 행동·무효 대상 클릭 시 AP 소모 없음.
- 전투 종료 후 다시 시작할 때 AP, HP, 슬롯, 큐 모두 초기화.

## 9. 재미 검증 질문
- 전방/중앙/후방 배치가 실제로 타깃 선택과 위험 관리에 영향을 주는가?
- AP를 한 번에 소모하는 것과 남겨두는 것 사이에 선택 가치가 있는가?
- 행동 순서와 기습 선공이 전투 판단을 바꾸는가?
- 위치 교환과 무기 변경이 단순 클릭 낭비가 아니라 유의미한 전략인가?
- 6인 수동 조작이 지나치게 느리거나 번거롭지 않은가?

## 10. 의도적으로 확정하지 않는 사항
- 최종 캐릭터 스탯·스킬 비용·피해 계수·적 AI 전략·전열 효과·클래스·상성·상태이상·필살기 별도 자원·수집/육성/군사시설 경영 세부 규칙.
- 위 3절 임시 규칙은 구현 편의를 위한 교체 가능한 값이며 정식 게임 디자인 확정이 아님.
