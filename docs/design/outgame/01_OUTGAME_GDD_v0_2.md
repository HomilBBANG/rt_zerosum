# 로튼 게임_전쟁 — 아웃게임 기지 운영 GDD v0.2

> 목적: 기지를 관찰하고, 시설을 해금하며, 인물에게 지시하고, 재정을 관리하는 **플레이 가능한 아웃게임 프로토타입**을 제작.  
> 연계 문서: `02_NPC_SCHEDULE_EDITOR_v0_1.md`, `03_IMPLEMENTATION_HANDOFF_v0_1.md`, `04_DECISION_LOG_v0_1.md`.

## 1. 한 문장 기획

플레이어는 **얼굴이 등장하지 않는 군 기지 총괄 책임자**가 되어, 2048년 4월 7일부터 살아 움직이는 기지를 관찰하고 시설을 해금하며 대원들을 훈련·업무·청소에 배치하고, 주간 결산과 월간 장군 점검을 관리한다.

### 핵심 플레이 루프 [확정 요소의 구조화]

`기지 관찰 → 대원과 대화/명령 → 시설 해금·업무 지정 → 시간 진행 → 위생·이벤트·대원 동선 변화 → 주간 결산/월간 점검 → 다음 운영`

- **인게임**: 별도 개발된 라운드제 AP 전투 프로토타입과 연계 예정. 전투 시스템을 아웃게임 구현 과정에서 임의로 재설계하지 않는다.
- **아웃게임**: 《Fallout Shelter》처럼 한 화면에서 방·인물을 관찰하는 기지 관리 화면. **자유로운 방 건설은 하지 않는다.**
- **스토리**: 기존의 메인 스토리 진행 중심이라는 방향을 유지하되, 구체적인 이벤트·조건·대사는 미정.

## 2. 확정 사항 — 기획 원문을 시스템 규칙으로 정리

| 구분 | 확정 규칙 |
|---|---|
| 카메라 | WASD로 이동하여 기지를 자유롭게 살펴본다. |
| 시설 구조 | 기지에 사전 배치된 잠금 시설을 **달러를 지불해 해금**한다. 위치를 지정해 신축하지 않는다. |
| 잠금 표현 | 해금 전 방을 **검은색**으로 표시한다. |
| 층 구조 | 기본 개방은 **지상 1층과 지하 1층**. 초기에는 총 **3개 층 규모**까지 기지가 만들어져 있으며 이후 확장할 계획. 나머지 층의 번호·개방 방식은 아직 미정. |
| 날짜 | **2048년 4월 7일 시작**, 24시간이 지나면 다음 날짜로 넘어간다. |
| 인물 생활 | 인물마다 자주 머무는 장소가 있고, **주 단위 이동·생활 스케줄**이 있다. 인물은 AI로 동선을 이동한다. 스케줄 에디터 필요. |
| 직접 대화 | 캐릭터 클릭 시 대화할 수 있다. |
| 엿듣기 | 두 명 이상의 캐릭터가 대화할 때 말풍선을 클릭하면 대화를 엿들을 수 있다. |
| 요청 이벤트 | 머리 위 `!`가 있는 캐릭터와 대화하여 요청을 확인하고 수락할 수 있다. |
| 주인공 | 기지의 총괄 책임자이며, 화면에 따로 주인공 캐릭터를 표시하지 않는다. |
| 재정 | **주 단위 행정 지원금** 수령 및 **주 단위 결산**. |
| 수익 활동 | 대원에게 일을 시켜 달러를 벌 수 있다. **외부 의뢰 수락**과 **캐릭터에게 작업 지시**가 가능하다. |
| 장군 점검 | **월 1회 랜덤 시점**에 장군이 기지를 점검한다. 환경 미화 점수가 장군 만족도로 반영되어 **그 주 결산에서 추가 달러**를 받는다. |
| 위생 | **매일 랜덤으로 기지가 더러워진다.** 캐릭터 우클릭 → 청소 → 해당 기지/장소 클릭 시 청소하러 이동한다. |
| 위임 | 특정 캐릭터는 청소를 직접 하지 않고 다른 캐릭터에게 시키기도 한다. 어떤 캐릭터인지·조건은 미정. |
| 기지 육성 | 대원 훈련, 무기 제작, 무기 강화는 기지에서 한다. |
| 아트 | 미국 카툰풍의 단순 셀 셰이딩, 원색 조명이 뚜렷하게 대조되는 실내 연출. 캐릭터 화풍은 앞서 제공된 5번 레퍼런스 기준. |

## 3. 화면 구성 및 입력

### 3.1 메인 기지 화면 [확정+UI 기술 제안]

- **메인 뷰**: 건물 단면을 세로·가로로 둘러본다. 방이 해금되면 내부 공간과 캐릭터 활동을 관찰한다.
- **잠금 방**: 방 전체를 검게 처리. 클릭 시 해금 패널에 **달러 가격 / 해금 버튼 / 부족 금액 안내**를 표시한다. 패널의 세부 구성은 [구현 제안].
- **대원**: 방/복도를 주간 스케줄대로 이동. 클릭해서 대화.
- **대화 말풍선**: 대원 간 대화가 열렸을 때만 노출, 클릭 시 엿듣기 대화창.
- **요청 마커 `!`**: 이벤트 보유자의 머리 위에 표시, 클릭 시 관련 대화/요청 수락.
- **HUD [기술 제안]**: 날짜·시간, 달러, 다음 결산 정보, 기지 위생/점검 결과, 선택 인물 명령 메뉴.

### 3.2 입력 [확정 동작+세부 임시]

| 입력 | 결과 | 상태 |
|---|---|---|
| `W/A/S/D` | 기지 카메라 이동 | **확정** |
| 캐릭터 좌클릭 | 직접 대화 | **확정** |
| 다른 캐릭터끼리의 대화 말풍선 좌클릭 | 엿듣기 | **확정** |
| `!`가 있는 캐릭터 클릭 | 요청 대화 및 수락 가능 | **확정** |
| 캐릭터 우클릭 → `청소` → 장소 클릭 | 해당 캐릭터에게 청소 지시 | **확정** |
| 잠금 방 클릭 → 달러 지불 | 방 해금 | **확정된 동작 / UI 제안** |
| 휠 줌 | 관찰 거리 조절 | **임시 편의 기능** |
| `Esc` | 현재 명령/대화창 닫기 | **임시 편의 기능** |

> 클릭 충돌 우선순위 [임시]: UI > 요청 마커·말풍선 > 캐릭터 > 시설. 같은 지점에서 클릭이 중복 처리되지 않게 한다.

## 4. 시설 및 해금 시스템

### 4.1 시설 데이터

- `facility_id`, `floor_id`, `room_bounds`, `unlock_cost_usd`, `unlock_state`, `function_tags`, `entry_points`, `internal_waypoints`, `cleanliness`, `occupants`, `active_jobs`.
- 잠금된 방도 **고정된 공간·충돌·출입구 데이터**를 가지며, 해금 여부만 바뀐다. 따라서 절차적 방 배치는 필요하지 않다.
- **초기 개방 구역은 지상 1층과 지하 1층.** 총 3개 층은 씬에 존재하되 나머지 층은 잠금 구역으로 처리하는 방식이 [프로토타입 가정].

### 4.2 해금 플로우

1. 카메라로 검은 방 발견.
2. 방 선택 → 달러 비용 확인.
3. 해금 요청 → 보유 달러 검증 → 결제 → 방 시각·충돌/진입 가능 여부 갱신.
4. 방에 연결된 인물 경로·스케줄 목적지가 유효해짐.
   - **[확정] 시설 해금에 따른 생활 변화:** 해금된 공간에 맞춰 NPC의 방문 장소·주간 생활 동선/행동이 달라질 수 있어야 한다. 단, 구체적인 변화 패턴은 개별 NPC·시설 데이터에서 설정한다.
5. 다시 접근했을 때 해금 상태가 저장되어 있음.

**필수 예외:** 달러 부족, 이미 해금된 방, 잠금 구역이 일시적인 경로 목적지로 선택된 상황. NPC는 해금되지 않은 방으로 입장하지 않는다.

### 4.3 해금에 따른 NPC 생활 변화 [사용자 승인]

- 신규 시설 해금은 출입 가능 여부만 변경하는 데 그치지 않고 **캐릭터들의 생활에 변화를 발생시키는 시스템**과 연결한다.
- NPC의 주간 일정은 해금 조건에 따른 분기를 지원한다. 예를 들어 해당 시설이 열려 있을 때만 그 공간에 방문하는 스케줄 블록을 활성화할 수 있다. [구현 예시, 개별 생활 패턴 미확정]
- 시설별로 어떤 캐릭터의 어떤 행동이 변경되는지는 에디터 데이터로 설정한다. 해금 직후 무조건 전 인원이 방문하는 등의 규칙은 두지 않는다.
- 이미 진행 중인 청소·작업·대화와 스케줄 변경이 충돌하면 기존 명령 우선순위에 따라 새 목적지를 재평가한다. [구현 가정]

### 4.4 시설 종류

실제 기지 시설 목록은 **미정**. 초기 프로토타입에서는 `생활 구역 / 청소 가능한 공용 구역 / 훈련실 / 작업실 / 잠금 방` 등의 **더미 기능 태그**로 동작을 시험한다. 이 명칭들은 설정 확정이 아니다.

## 5. 시간·일정 시스템

### 5.1 세계 시계

- 시작 날짜: **2048-04-07**. 달력상 화요일이지만, 결산 요일을 화요일에 고정한다는 뜻은 아니다.
- 시계: 00:00~23:59, 경과 24시간마다 날짜 +1. 실제 1분이 게임 몇 분인지는 [미정]으로 **설정값** 처리.
- 일 전환 시: 일일 오염 추첨, 일일 작업 상태/스케줄 날짜 갱신, 해당 날의 이벤트 트리거 평가.
- 주 전환 시: 주간 스케줄 순환, 정기 지원금 지급, 주간 결산.
- 월 단위: 한 달당 장군 점검 1회 발생. 점검 이후 동일 월 재점검 방지.

### 5.2 주 단위 스케줄

- **7일 × 하루 시간대**에 대해 캐릭터별 `장소 + 행동 + 이동 목적`을 기술한다.
- 자주 머무는 장소(`preferred_locations`)를 따로 두고, 미지정 시간대에 사용할 수 있게 설계한다 [구현 제안].
- 시간대 전환 시 현재 작업/대화 등 예외 상황을 처리하고 유효한 목적지까지 이동한다.
- 일정 편집 방식은 별도 문서 `02_NPC_SCHEDULE_EDITOR_v0_1.md`.

### 5.3 게임 시간 속도 및 일시정지 [프로토타입 임시]

- **기본 테스트값**: 현실 1초 = 게임 1분, 설정 또는 디버그 패널에서 변경 가능. 이 수치는 최종 밸런스가 아니다.
- 대화창·시설 해금창이 열려 있을 때 시계 멈춤, 캐릭터 이벤트 타이머도 일시정지 [임시].
- 게임을 종료한 동안의 **오프라인 시간 진행은 사용하지 않음** [임시].
- 디버그 도구에 `+1시간`, `다음 날`, `다음 주`, `다음 달`을 배치해 시간 의존 기능을 빠르게 검증한다.

## 6. NPC 생활·경로·대화

### 6.1 NPC 상태 [기술 설계]

`IDLE / MOVING / STAYING / CHATTING / PLAYER_DIALOGUE / ASSIGNED_WORK / CLEANING / TRAINING / UNAVAILABLE`

- NPC는 스케줄에 따라 목적지를 선택하고, **시설 간 통로 그래프 → 시설 내 웨이포인트**로 이동.
- NPC가 어떤 방을 자주 사용하는지, 주간 계획 및 예외 행동은 데이터로 관리한다. 에디터에서 수정 가능해야 한다.
- 대화가 진행될 때 캐릭터가 이동해 버리거나 지시가 중복 실행되지 않도록 **행동 우선순위/중단-재개 규칙**을 둔다.
- **청소를 타인에게 위임할 수 있는 특정 캐릭터**는 `delegate_cleaning` 같은 성향 플래그 또는 별도 행동 룰로 처리하되, 위임 가능한 실제 인물 목록은 미정.

### 6.2 대화 유형

1. **직접 대화**: 캐릭터 클릭 → 대화창.
2. **대원 간 대화**: 조건이 맞으면 캐릭터끼리 대화 애니메이션 및 말풍선 생성 → 말풍선 클릭 시 전체/관련 대사를 엿듣기.
3. **요청 대화**: `!`가 붙은 캐릭터 클릭 → 요청 내용을 듣고 수락 가능. 거절/보류/기한/보상 여부는 개별 이벤트 데이터로 처리 [구현 제안; 공통 규칙 미확정].

### 6.3 엿듣기로 스토리 발견 [사용자 승인]

- NPC들끼리 나누는 대화를 엿듣는 행위를 **인물 관계·사건·메인 스토리와 관련된 정보를 발견하는 경로**로 사용한다.
- NPC 간 대화 중 표시되는 말풍선을 클릭하면 대화 내용을 확인할 수 있으며, 스토리 정보가 포함된 대화는 관련 대사·이벤트 ID와 연결한다.
- 단서의 종류, 목록, 수집 UI, 메인 스토리 분기 여부는 **미정**이다. 별도의 수집 재화나 호감도 보상을 임의로 도입하지 않는다.
- 개발 검증용으로 일반 대화 1개와 스토리 관련 대화 1개를 구분해 동작을 확인한다. [임시 테스트 데이터]

대화 스크립트는 **데이터 기반 ID 참조**. 캐릭터 스케줄에 대사를 하드코딩하지 않는다.

## 7. 일일 위생과 청소

### 7.1 오염 생성 [확정 동작 + 임시 생성 규칙]

- 하루가 바뀔 때 기지 내 유효한 해금 구역을 대상으로 오염 이벤트를 랜덤 생성.
- 더러운 곳을 화면에 보이도록 표시한다. 장소 단위 점수·오염 오브젝트 위치는 [임시 설계].
- 위생/미화 평가는 월간 장군 점검 시 만족도에 영향을 준다.

### 7.2 청소 명령

`인물 우클릭 → 청소 선택 → 오염된 구역/장소 클릭 → 이동 → 청소 행동 → 오염 제거 → 상태 갱신`

- 청소 대상이 유효하지 않거나 목적지에 갈 수 없으면 **명령을 실행하지 않고 이유를 표시**.
- 청소 명령은 특정 캐릭터에게 내려도, 해당 캐릭터가 다른 인물에게 위임하는 행동이 발생할 수 있음 [확정 가능성].
- 위임 여부/대상은 캐릭터별 룰로 연결, 실제 위임 빈도와 타깃은 [임시].
- 청소·동선 충돌 시에는 스케줄보다 **플레이어 명령을 우선**하는 방식으로 첫 버전 구현 [임시]. 완료 후 원래 스케줄 복귀.

### 7.3 환경 미화 점수 [기술 제안]

- 각 시설에 `cleanliness` (0~100 임시값)와 `trash_instances`를 보유.
- 기지 전체 점수 = 접근 가능한 해금 시설의 점수 집계. 정확한 계산식은 밸런싱 후 결정.
- 점검 시점의 점수 스냅샷을 생성하여 같은 주 결산 추가 달러를 산정한다. 실제 보너스 액수/등급은 임시 데이터.

## 8. 경제·주간 결산·장군 점검

### 8.1 화폐와 원장

- 화폐: **USD 달러**.
- 수입: 주간 행정 지원금, 배정한 업무/외부 의뢰 수익, 장군 점검에 따른 결산 보너스.
- 지출: 시설 해금 비용. 훈련/제작/강화 비용 여부는 미정이므로 **프로토타입에서 함부로 확정하지 않는다**.
- 동일 거래가 중복 반영되지 않도록 `ledger_entry_id`, `date_time`, `source_type`, `amount`, `reference_id`를 가진 원장 구조 [기술 설계].

### 8.2 주간 정산

1. 결산 주기 도달.
2. 해당 주의 행정 지원금 + 업무/외부 의뢰 수입 + 장군 점검 보너스(해당 주만) 반영.
3. 결산 패널에 항목별 내역 및 잔액 표시.
4. 정산 처리 여부를 기록해 **중복 지급 방지**.

**주의:** 실제 주 시작/마감 요일은 사용자 미정. 프로토타입에서는 시작 날짜로부터 **게임 내 7일 단위**로 결산하는 방식으로만 테스트한다 [임시]. 사용자가 요일을 정하면 쉽게 교체 가능.

### 8.3 외부 의뢰와 작업 지시

- 플레이어는 의뢰를 받아 대원에게 일을 배정할 수 있음 [확정].
- 프로토타입에서는 `의뢰 목록 → 의뢰 선택 → 대원 지정 → 작업 시간 경과 → 완료 → 수익 반영` 플로우를 최소 구현 [임시].
- 성공률·부상·전투 발생·복귀 여부는 **미정**. 별도 시스템이 생기기 전엔 일단 고정 완료 판정으로 검증할 수 있음 [임시].

### 8.4 장군의 월 1회 점검

- 매 게임 월마다 **한 번**, 월 내 일정 시점을 랜덤으로 결정.
- 점검 시 **환경 미화 점수**를 바탕으로 장군 만족도를 평가.
- 보상은 점검이 발생한 **그 주의 결산에 추가 달러**로 지급.
- 월별 `inspection_done`과 주간 `pending_bonus`로 재점검·중복 보상 차단.
- **임시 특수 처리**: 게임 시작일인 2048-04-07에 이미 해당 월 1회 점검 일정이 준비되도록 스폰 시점에 4월의 남은 날짜 중 임의 시점 선정.

## 9. 훈련·제작·강화와 전투 연계

세 기능은 모두 기지에서 수행한다는 것이 **확정**이다. 세부 비용/시간/효과는 시스템 완성 후 밸런싱한다.

| 기능 | 최소 입력 | 최소 출력 | 상태 |
|---|---|---|---|
| 대원 훈련 | 캐릭터·훈련 선택 | 대원 성장 데이터에 결과 반영 | 기능 확정, 수치·세부 규칙 임시 |
| 무기 제작 | 제작 메뉴·레시피 선택 | 인벤토리에 무기 지급 | 기능 확정, 레시피/자원 미정 |
| 무기 강화 | 무기·강화 선택 | 무기 강화 데이터 갱신 | 기능 확정, 확률/효과 미정 |

- 전투 프로젝트와는 `character_id`, `weapon_id`, `inventory`, `progression` 같은 **공유 데이터 식별자**로 연결.
- 외부 전투 씬에 진입해 전투를 직접 실행하는 UI 플로우는 지금 문서에서 확정하지 않는다.
- 프로토타입은 **더미 성장 결과/더미 무기**로 기지 작업 → 저장 → 전투 편성에 반영할 데이터 연결을 확인한다.

## 10. 상호작용 이벤트 우선순위 [프로토타입 임시]

게임을 멈추지 않고 자연스럽게 인물이 살아 움직이려면 충돌 규칙이 필요하다.

1. 현재 진행 중인 플레이어 대화/선택은 즉시 끊지 않음.
2. 긴급/직접 작업 지시를 받으면 NPC가 가능한 시점에 기존 스케줄 중단 후 이동.
3. 엿듣기 가능한 NPC끼리의 대화는 스케줄 이동 때 중단/종료 가능.
4. 작업 종료 후 현재 요일·시간대의 스케줄 재조회.
5. 해금되지 않은 시설이 목적지면 지정된 대체 장소로 이동.

> 위 충돌 처리 우선순위는 게임 세계관 규칙이 아니라 **프로토타입 실행을 위한 교체 가능한 로직**이다.

## 11. 아웃게임 최소 플레이어블 프로토타입(MVP)

### MVP-0: 화면과 이동
- 3층 높이 기지 단면 씬: 지상 1층/지하 1층 개방, 추가 1개 층은 잠금 상태로 표현 [층 번호 미정].
- WASD 카메라 이동, 해금되지 않은 방 검정 표시, 달러 지불/해금.
- 실제 게임 아트가 없으면 임시 스프라이트로 기능 우선 테스트.

### MVP-1: 살아 있는 대원
- 테스트 대원 3~4명(임시 수)과 기본 주간 스케줄 에디터.
- 일정 이동·대기·캐릭터 클릭 대화, NPC끼리 대화/엿듣기, `!` 요청 이벤트.

### MVP-2: 날짜와 기지 위생
- 2048-04-07 시작, 24시간 진행, 날짜 변경.
- 일일 랜덤 오염, 청소 명령, 위임 성향 테스트, 청결 상태 표시.

### MVP-3: 재정 루프
- 달러 원장, 주간 지원금 및 정산, 작업/외부 의뢰 수익.
- 월 1회 랜덤 점검 → 위생 점수 → 해당 주 보너스 지급.

### MVP-4: 인게임과 데이터 연결
- 더미 훈련·제작·강화 UI와 결과 데이터 반영.
- 전투 프로토타입의 캐릭터/무기와 최소한의 데이터 연동, 세이브/로드.

**우선순위:** 제작 초기에는 **카메라·해금·시계·NPC 주간 이동·대화·청소·주간 결산·월간 점검**이 화면 하나에서 연결되는 것을 우선 확인. 상세 아트, 동작 애니메이션, 긴 스토리, 전 인물별 방대한 대사는 후순위.

## 12. 수용 기준(프로토타입 완료 체크)

- [ ] 게임이 2048-04-07에서 시작하고 24시간마다 정확히 1일 증가한다.
- [ ] 열린 구역과 검은 잠금 방이 명확히 구분된다. 달러 부족/정상 결제/중복 클릭을 모두 처리한다.
- [ ] 플레이어가 방 위치를 임의로 지정·신축할 수 없다.
- [ ] WASD로 기지 화면을 둘러볼 수 있으며 HUD와 월드 UI가 서로 간섭하지 않는다.
- [ ] 한 인물이 최소 7일치 시간대별 경로를 따라 움직이고, 방이 잠기면 대체 루트로 안전하게 이동한다.
- [ ] 시설을 해금했을 때 지정된 NPC의 후속 방문/생활 일정이 달라지는 사례를 확인할 수 있다.
- [ ] 캐릭터 클릭 대화, 말풍선 엿듣기, `!` 요청 수락이 서로 구분된다.
- [ ] 엿들은 NPC 대화를 통해 스토리 관련 대사가 노출되는 검증 시나리오가 있다.
- [ ] 우클릭 → 청소 → 장소 클릭이 정상 실행되고, 선택한 인물이 청소하거나 정해진 위임 룰을 사용한다.
- [ ] 날짜를 넘길 때 랜덤 위생 오염이 생성된다.
- [ ] 연속 주간 결산에서 행정 지원금과 작업 수익이 **한 번씩** 반영된다.
- [ ] 매월 점검은 정확히 1회만 발생하며, 보너스는 해당 주 결산에만 나타난다.
- [ ] 저장/불러오기 후 잠금·달러·날짜·NPC 위치·위생·정산/점검 상태가 복구된다.
- [ ] 훈련·제작·강화의 최소 실행 결과를 캐릭터/무기 데이터로 확인할 수 있다.

## 13. 아직 결정되지 않은 핵심 방향

- 실제 **시설 리스트와 3개 층의 정확한 이름·배치도**.
- **시간 스케일**(현실 몇 분 = 게임 하루)과 시간을 멈추는 시점, 장기 오프라인 진행 여부.
- 주간 결산의 요일·지출 종류·수익 산정 및 작업 실패/위험 요소.
- 미화 점수의 확정 계산식과 장군의 점검 연출/성격.
- 개별 NPC 캐릭터 설정, 관계, 상호작용 분기, 위임 캐릭터 목록.
- 훈련·제작·강화의 실제 규칙과 본편 전투/스토리 연결 방식.

**이 항목들은 기획자가 결정하기 전까지 임시값 또는 비활성화 상태로 둔다.**

## 14. 추가로 논의하면 좋은 아이디어 [아래 항목들은 전부 미승인]

> 시설 해금에 따른 생활 변화와 엿듣기로 스토리 발견은 사용자 승인으로 본문 4.3절·6.3절에 반영했으며, 아래 미승인 제안 목록에서는 제외했다.

| 아이디어 | 기대 효과 | 범위 위험 |
|---|---|---|
| **주간 운영 보고서**: 달러·청소·의뢰·대원 활동을 한 장에 요약 | 일주일 운영이 손에 잡히고 결산에 의미가 생김 | UI 및 로그 설계 추가 |
| **업무 충돌/불만 대사**: 청소 중 훈련을 명령하면 캐릭터 반응 | 개성이 대화와 운영에 연결됨 | 대사량/상태기계 증가 |
| **점검 대비 정리 모드**: 위생이 안 좋은 방 빠르게 순회·명령 | 장군 방문 전에 전략적 판단 가능 | 경고 UI만으로 시작 가능 |

**추천 논의 순서:** (1) 시설 지도와 해금 순서 → (2) 시간 스케일 → (3) 인물별 생활·직업과 대화 → (4) 경제/점검 → (5) 훈련·제작·강화 심화. 세부 구현 수치는 그때그때 임시값으로 처리.
