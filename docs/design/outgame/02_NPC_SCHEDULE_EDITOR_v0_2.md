# 캐릭터 주간 동선·행동 에디터 명세 v0.2

> 지위: **에디터 필요 / 캐릭터별 주간 동선 / 자주 머무는 장소 / 동선 AI**는 사용자 확정. 아래 에디터 UI·데이터 필드·우선순위는 **구현용 기술 제안**이며 캐릭터 성격·스토리 설정을 확정하지 않는다.

## 1. 에디터 목적

디자이너가 코드를 고치지 않고 NPC의 **월~일, 시간대별 목적지와 행동**을 수정하고 즉시 기지 씬에서 실행·검증할 수 있게 한다. 모든 NPC에게 매 순간 상세 루트를 하드코딩하지 않도록, 시간표와 자동 경로 탐색을 분리한다.

## 2. 제안 에디터 화면

```text
┌───────────────────────────────────────────────────────────────────────┐
│ 캐릭터 선택 [NPC_A ▼]  즐겨 찾는 장소 [공용실 / 숙소 ...]  [검증] [시뮬레이션] │
├─────────────────┬─────────────────────────────────────────────────────┤
│ 시설 목록/태그    │ 주간 시간표 (요일 탭: 월 화 수 목 금 토 일)              │
│ - 시설 A         │ 00:00 ─── 휴식 @ 시설 A                               │
│ - 시설 B         │ 08:00 ─── 이동 @ 시설 B                               │
│ - 시설 C (잠금)  │ 09:00 ─── 업무 @ 시설 B                               │
│                 │ 12:00 ─── 식사 @ 시설 C (잠금 경고)                    │
│ 행동 목록        │ 13:00 ─── 자유시간 @ 선호 장소                         │
│ 이동/대기/대화    │ + [시간 블록 추가]                                    │
├─────────────────┴─────────────────────────────────────────────────────┤
│ 2D 시설 단면 미리보기 / 경로·목적지 표시 / 시간 스크러버 [▶ 2x 8x]         │
├───────────────────────────────────────────────────────────────────────┤
│ 검사 결과: [경로 불가 1] [시간 겹침 0] [잠금 목적지 1] [참조 누락 0]       │
└───────────────────────────────────────────────────────────────────────┘
```

## 3. 편집 항목

| 단위 | 항목 | 설명 |
|---|---|---|
| 캐릭터 | `npc_id`, `display_name`, `preferred_facility_ids` | 자주 머무는 장소와 NPC 식별자 |
| 주간 계획 | `weekday`(0~6), `start_minute`, `end_minute` | 주당 반복되는 시간 구간 |
| 일정 블록 | `target_facility_id`, `target_point_id`, `activity_id` | 목적지와 수행 행동 |
| 조건 | `required_unlocks`, `condition_id`, `fallback_facility_id` | 방 잠금/이벤트에 따라 대체 일정 |
| 행동 | `action_type`, `duration`, `dialogue_id`, `animation_id` | 대기, 업무, NPC 대화 등 |
| 위임 성향 | `delegation_rules` | 특정 캐릭터가 청소를 다른 캐릭터에게 시키는 조건 |
| 임시 명령 | `command_type`, `target_id`, `issuer`, `resume_schedule` | 플레이어 청소·업무 지시 처리 |

## 4. 시설 해금과 생활 변화 [기능 확정 / 편집 방법은 기술 제안]

- 사용자가 승인한 기능: **시설 해금에 따라 NPC의 생활 장소와 주간 행동 동선이 변할 수 있어야 한다.**
- 편집기에서는 `required_unlocks` 같은 해금 조건과 `fallback_facility_id` 등의 잠금 상태 대체 일정을 함께 설정할 수 있도록 한다.
- 해금 직후 기존 계획을 다시 평가하고 조건이 바뀐 구간부터 새 목적지를 적용한다. [구현 가정]
- 모든 NPC의 실제 변화 내용은 설정 데이터로 작성하며, 임의로 캐릭터별 성격이나 스토리 패턴을 확정하지 않는다.

## 5. 엿듣기 스토리 이벤트 [기능 확정 / 연결 방법은 기술 제안]

- 사용자가 승인한 기능: **NPC끼리의 대화를 엿들어 스토리 관련 정보를 발견할 수 있다.**
- 대화 항목에는 `conversation_event_id`, `dialogue_id`, 필요 시 `story_event_id` 등을 연결한다.
- 실제 단서의 내용·스토리 분기·영구 기록 화면은 미정. 프로토타입은 스토리 관련 대사 1개가 정상 표시되는지만 검증한다.

## 6. 기능 요구사항 [기술 제안]

1. **요일별 시간표**: 시간 블록 복사·붙여넣기, 반복 패턴 복제, 시간 충돌 표시.
2. **씬 경로 표시**: 방의 출입구/웨이포인트를 에디터에서 선택. 자동 경로가 가능한지 즉시 검증.
3. **잠금 조건**: 목표 방이 잠겨 있을 때 경고 및 대체 장소 지정.
4. **실행 미리보기**: 날짜·시간 스크러버로 특정 시각의 위치/행동 확인. 선택한 NPC에만 빠른 테스트 가능.
5. **대화 조건**: 두 인물이 가까워지고 일정이 겹치면 대화 후보 생성. 엿듣기 말풍선과 대사 ID 연결.
6. **요청 마커 `!`**: 캐릭터·날짜·사전 조건을 이벤트 ID와 연결; 수락 후 중복 노출 방지.
7. **디버그**: 현재 상태·다음 목적지·경로 실패·일정 우선순위·대체 경로 확인.
8. **저장/로드**: `Resource (.tres)` 또는 JSON 중 하나로 데이터 직렬화. 최종 포맷은 기술 선택.

## 7. 제안 실행 알고리즘

```text
매 시뮬레이션 틱:
  게임 날짜/요일/시각 조회
  NPC의 유효한 명시적 명령 확인
  명령 없으면 현재 시각의 주간 일정 블록 찾기
  목적지 시설이 열려 있고 접근 가능한지 검사
  접근 불가 시 해당 일정의 fallback_facility_id 사용
  목표로 경로를 탐색하고 이동
  도착 시 활동 애니메이션/대화 조건 수행
  활동 완료·시간 변경·명령 중단 시 새 일정/명령을 재평가
```

> 모든 NPC가 매 프레임 전체 경로를 재계산하지 않는다. 목적지가 바뀌거나 길이 막힐 때만 경로 재평가하는 구조 권장.

### NPC 간 대화 트리거 [임시]

- 두 NPC가 같은 해금된 방에 있고 대화 가능 시간/상태일 때 `conversation_event_id` 조건을 확인.
- 대화 중 해당 캐릭터들이 잠시 멈추며 말풍선을 노출한다.
- 클릭하면 플레이어에게 엿듣기 대사를 제공한다.
- 이벤트 발동 횟수와 우선순위는 별도 데이터로 관리해 대화가 무한 반복되지 않게 한다.

### 청소 위임 [임시]

- `cleaning_command` 수신 → 위임 가능한 캐릭터이면 조건에 따라 **실제 작업자**를 찾아 작업 전달.
- 위임된 대원도 접근 가능한 장소인지 확인.
- 실패하면 전달 실패를 표시하고 원래 명령자가 직접 처리할지 여부는 임시/별도 룰로 결정.
- 명령 요청자(`requested_npc_id`), 실제 수행자(`executing_npc_id`), 목적지와 결과를 각각 로그로 보존.

## 6. 샘플 데이터 — 모든 내용 테스트 전용

```json
{
  "npc_id": "npc_test_01",
  "preferred_facility_ids": ["room_lounge", "room_quarters"],
  "weekly_schedule": [
    {"weekday": 1, "start_minute": 480, "end_minute": 720, "target_facility_id": "room_lounge", "activity_id": "idle"},
    {"weekday": 1, "start_minute": 720, "end_minute": 1080, "target_facility_id": "room_training", "activity_id": "train", "fallback_facility_id": "room_lounge"}
  ],
  "delegation_rules": {"can_delegate_cleaning": false}
}
```

- `weekday`: 월=0, 화=1, …, 일=6인 **기술 표기**. 2048-04-07은 화요일.
- 실제 NPC 이름·성격, 방 이름, 직업, 행동과 시간표는 승인되기 전까지 **더미**.

## 7. 에디터 완료 조건

- [ ] NPC 한 명의 7일 시간표를 UI에서 작성/수정/저장한다.
- [ ] 대화/청소/업무 명령 후 현재 시각에 맞는 일정으로 복귀한다.
- [ ] 잠긴 방 목적지·경로 단절·시간 중첩·이벤트 ID 참조 오류를 검사한다.
- [ ] 씬 실행 없이 시간 스크러버로 특정 일자/시간의 예상 목적지를 확인할 수 있다.
- [ ] NPC 두 명의 대화 시작/엿듣기와 특정 NPC의 청소 위임을 테스트할 수 있다.
- [ ] 에디터 변경 결과가 게임 재시작 후에도 남는다.

## 8. 구현 순서

1. NPC/시설 ID 및 주간 스케줄 데이터 타입.
2. 7일 타임라인 편집 UI.
3. 시설 연결 그래프와 목적지 이동.
4. 실행 미리보기/진단 패널.
5. 청소·업무 명령 인터럽트 및 복귀.
6. NPC 대화와 요청 `!` 이벤트 연결.

> 사용자에게 확정을 요구할 일이 아니라면 에디터 버튼 위치·데이터 폴더 구조·더미 시간표 등은 개발 과정에서 임시 결정 가능.
