# RT Zerosum — 전투 + 기지(아웃게임) 플레이어블 프로토타입 (Godot 4.7)

횡스크롤 턴제 6인 AP 전투 프로토타입. `docs/design/PROTOTYPE_GDD_v1_0.md` 의 확정 규칙과 임시값을 구현했고,
**같은 전투 규칙 위에 2D 표현(원화 + 구역 마스크 셰이더)과 3D 표현(셀 셰이더 + 실광원) 두 가지 뷰**를 올려
그래픽 방향(2D vs 3D)을 비교·결정할 수 있게 했습니다. 비교 결과는 `docs/2D_vs_3D_comparison.md` 참조.

## 설치 (노트북·데스크톱 공통, 명령 한 줄)
각 기기의 `/Users/eunjikim/Game/zerosum` (= `~/Game/zerosum`, Windows 는 `C:\Users\<이름>\Game\zerosum`)에 프로젝트를 받고,
Godot 4.7 이 없을 때만 macOS 는 `/Applications/Godot.app` 하나에 설치해 바로 실행합니다(이미 있으면 재사용). 저장소가 공개라 GitHub 로그인은 필요 없습니다.

**Windows** — 시작 메뉴에서 PowerShell 을 열고 붙여넣기:
```powershell
irm https://raw.githubusercontent.com/HomilBBANG/rt_zerosum/main/setup/install_windows.ps1 | iex
```
설치가 끝나면 바탕화면에 **RT Zerosum** 바로가기가 생깁니다. 이후 실행은 바로가기 또는 `Game\zerosum\play.bat`.

**macOS (노트북·컴퓨터 공통)** — 터미널에 붙여넣기:
```bash
curl -fsSL https://raw.githubusercontent.com/HomilBBANG/rt_zerosum/main/setup/install.sh | bash
```
이후 실행은 Finder 에서 `Game/zerosum/play.command` 더블클릭, 또는 `~/Game/zerosum/play.sh`.
`~/Game/zerosum` 폴더가 이미 있고 다른 파일이 들어 있어도 지우지 않고 그 자리에 연결합니다. 저장소 파일과 이름이 겹치는 기존 파일(예: Godot 가 만든 `.gitignore`)은 `_backup_before_install_날짜/` 폴더로 옮겨 둡니다.

**Godot 가 여러 개 깔렸을 때**: 아래 명령이 Mac 의 Godot 를 모두 찾아 목록을 보여주고, y 를 입력하면 4.7 하나만
`/Applications/Godot.app` 에 남기고 나머지는 휴지통으로 옮깁니다(Finder 휴지통에서 복구 가능).
```bash
curl -fsSL https://raw.githubusercontent.com/HomilBBANG/rt_zerosum/main/setup/cleanup_godot.sh | bash
```

**업데이트**: 프로젝트 폴더에서 `git pull` 만 하면 됩니다 → 그다음 평소처럼 `play.command` / `play.sh` / `play.bat` 실행.
새 원화·애니메이션이 들어온 커밋이면 실행 스크립트가 알아서 리소스를 다시 임포트합니다(커밋이 바뀐 첫 실행에만, 최대 1~2분).
```bash
cd ~/Game/zerosum && git pull
```
git 이 없는 설치(zip)는 같은 설치 명령을 다시 실행하면 최신으로 받아옵니다.
**에디터로 열기**: `play.bat edit` / `./play.sh edit`. 에디터가 튕기면 `play.bat editlog` / `./play.sh editlog` 로 열어 같은 동작을 하고, 생긴 `editor_log.txt` 를 보내 주세요 (콘솔 창에 오류도 그대로 남음).
**다른 폴더에 설치**: macOS `curl ... | GAME_DIR=/경로 bash`, Windows `$env:GAME_DIR="D:\Game"` 를 먼저 지정.

> git 이 설치돼 있으면 두 기기 모두 `git pull` 로 같은 코드를 맞출 수 있습니다. 한쪽에서 수정한 뒤 다른 쪽에서 받으려면
> 수정한 기기에서 `git push` 할 권한(HomilBBANG/rt_zerosum 저장소 협업자)이 필요합니다.

## 게임 루프 · 아웃게임(기지 운영)
**타이틀 → 새 게임(또는 이어하기) → 기지 → `전투 출전` → 전투 배치(편성) → 전투 → 결과 → `기지로 복귀`** [임시 루프, 바뀔 수 있음].
기획: `docs/design/outgame/01~04` (사용자 제공), 구현 현황·수용 기준 대응표: `docs/design/outgame/05_IMPLEMENTATION_STATUS.md`.

- **기지 화면**: 배경은 **3D 단면 건물**(방마다 원색 스폿 조명·하드 섀도우, 셀 셰이딩), 건물 바깥은 **검정**.
  카메라는 **정면처럼 반듯한 직교 뷰**(원근 없음 — 방마다 같은 크기 사각형, 한 칸 ≈ 정사각형)이고 **방 안만 위에서 살짝(18°) 내려다보는** 구도라 바닥이 보입니다.
  처음엔 대원들이 있는 지상 1층·지하 1층을 크게(화면 세로 9m) 보여 줍니다. 대원은 2D 캐릭터 스프라이트(프레임 애니메이션)를 그 위에 덧그림.
  3개 층 (지상 1층·지하 1층 기본 개방, 지하 2층(임시) 잠금). `WASD` 이동 · `F11` 전체 화면.
  **확대/축소**: 마우스 휠(커서 위치 기준) · Mac 트랙패드 핀치 또는 두 손가락 위아래 · `Q`/`E` 누르고 있기 · `-`/`+` · 오른쪽 아래 `－ 100% ＋` 버튼 · `0` = 기본.
  범위 45%~250% (화면 세로 20m~3.6m): 최대 확대는 대원 원화(전신 약 760px)가 QHD 화면에서 원화보다 커지지 않는 한계, 최대 축소는 기지 전체가 보이는 정도. 3D 배경은 늘 QHD 로 다시 그려 어느 배율에서도 선명.
  카메라 각도·확대(화면 세로 m)는 `scenes/outgame/base_hub.tscn` 루트 노드 인스펙터 **카메라** 그룹 (실행 중 원격 탭에서도 즉시 반영).
- **시간**: 2048-04-07 (화) 08:00 시작, 현실 1초 = 게임 1분 [임시]. 위쪽 `정지/1x/4x/16x`, `Space` 정지/재개. 창이 열려 있으면 시계가 멈춤.
- **대원 6명** (전투 아군과 같은 인물): 주간 일정대로 방을 오가며 생활 (수면·식사·업무·잡담…).
  - **대원 클릭 = 선택** (발밑 노란 고리). 선택한 대원을 **한 번 더 클릭 = 선택 해제**. 대화 · 정보는 **우클릭 메뉴** (머리 위 **`!`** 면 대화에서 요청 → 수락, '정보 보기' = 화면 가운데 창). `Tab` 다음 대원, `Esc`·빈 곳 클릭 = 선택 해제.
  - 대원을 선택한 채 **방 클릭 = 그 위치로 걸어감**, **더블클릭 = 뛰어감** (걷는 중에 더블클릭해도 뛰기로 바뀜, 뛰면 2.2배 빠르고 피로 +). 선택 없이 방 클릭 = 시설 창.
  - **도착하면 그 방에서 우클릭(방이나 대원) = 그 방에서 할 행동**: 숙소 잠자기·쉬기 / 공용실 쉬기·잠자기(소파) / 식당 식사 / 훈련실 훈련 / 의무실 치료·휴식 /
    행정실·정문 업무·의뢰 / 무기고·PX 창 열기. 아래쪽 '어디서나' = 업무·훈련실로·의무실로·**지시 그만두기**.
  - 직접 보낸 대원은 그 방에 머물며(지시 대기) 행동하다가 **다음 일정 블록이 시작되면 일정대로** 돌아감 (잠자기는 피로 0 이 되면 일어남).
  - 대원 둘이 같은 방에서 쉬면 **말풍선** → 클릭하면 엿듣기 (스토리 대화 포함).
- **청결 요소는 없앰** (2026-10-30 — 오염 · 청결 점수 · 청소 지시 · 위생 점수 모두). 일정의 '청소' 활동은 생활 모습으로만 남음.
- **재정 (USD)**: 7일마다 주간 결산 = **주급(기본 주급 × 그 주 납품 비율)** + 그 주 작업·의뢰 수익 + 장군 추가금/차감. 수익은 완료 즉시 '미지급'으로 쌓였다가 결산 때 입금. 같은 거래는 원장 id 로 한 번만 반영.
  - 날짜 바(왼쪽 위)에는 **미지급 · 결산 D-day** 만.
- **전리품 창고**: 전투에서 이기면 스테이지마다 정한 아이템을 확률로 얻음(결과 화면에 표시), 대원과 **하루 첫 대화** 때 대원마다 정한 아이템을 확률로 건네받음. 위쪽 **`납품`** 창 아래에서 창고 확인.
- **납품** (위쪽 `납품` 버튼): 주마다 납품 목록 — **스토리 진행률**(완료한 퀘스트 비율 %)에 맞는 목록, 같은 진행률 목록이 여럿이면 주마다 번갈아. 물품마다 `1개 내기` · `모두 내기`(필요한 만큼만).
  **주급 = 기본 주급 × 납품 비율** (목록 개수 합 중 낸 개수) — 예: 기본 $150, 50% 납품 → $75.
- **장군 점검**: 매달 한 번 랜덤 시각에 장군이 와서 **아이템을 요구**(매번 다른 것) → `준다`(창고에 있어야 함) · `안 준다` · `나중에`(결산 전까지 `납품` 창에서 대답, 대답 없으면 거절).
  준다 = 그 주 결산 **추가금 +$40 · 충성심 +5** / 안 준다 = 그 주 결산 **차감 −$40 · 충성심 −10**. **장군 충성심** 게이지(0~100, 시작 50)는 `납품` 창 · 점검 창 · 원장에.

- **보급 데이터 = `data/supply.xlsx`**: 설정(기본 주급 · 장군 추가금/차감 · 충성심) · 아이템 · 전투 보상(스테이지마다, `*` = 모든 승리) · 대원 선물(확률 · 최소 친밀도) · 장군 요구(아이템 · 개수 · 가중치 · 대사) · 납품(진행률 % · 목록). 모두 [임시] 값, 실행 중 저장하면 다시 읽음. 처음 만든 스크립트 `tools/gen_supply_xlsx.py`.
- **훈련·제작·강화 → 전투**: 훈련 단계마다 전투 최대 HP +5, **무기고**(위쪽 `무기고` 버튼)에서 대원별 무기 3칸 장착·무기 제작(시간만)·강화(+1당 위력 +1). 기지에서 출전한 전투에 반영 [더미 수치].
- **계단**: 대원이 계단 칸의 지그재그 계단을 실제로 대각선으로 걸어 오르내립니다.
- **전투 발생**: `전투 출전` 버튼 말고도 기지 시간에 따라 전투가 일어납니다 (예시: 06:00 기준 **6시간마다** 00·06·12·18시). 발생하면 기지 시계가 멈추고 붉은 막대 `전투 배치로` → 편성 → 전투.
  규칙은 **Godot 에디터 상단 `전투 발생` 탭** (아래 참고).
- **체력·피로도·친밀도** (대원 좌클릭 → 카드): 체력(붉은) · 피로도(보라) · **친밀도(파스텔 노랑, 아웃게임에서만)** · 상태 이상.
  - 전투에서 잃은 체력은 기지로 그대로 돌아옵니다(쓰러지면 HP 1 + 부상). **상태 이상은 의무실 치료, 체력은 의무실 침대 휴식으로만 회복** — 우클릭 → `의무실로`.
  - 피로는 활동·전투로 오르고 **침대·소파·의자에서 잠을 잘 때만** 내려갑니다. 오브젝트마다 회복력이 다름(침대 > 의무침대 > 소파 > 의자). 대원은 침대에 눕고 의자·소파에 앉습니다.
  - 친밀도: 하루 첫 대화 +1, 요청 수락 +5, **PX(상점)** 에서 산 선물을 카드의 `선물하기`로. **대원마다 좋아하는 선물과 오르는 양이 다름**
    (단 가죽 장갑 +16 · 키라 행운 부적 +14 · 이선 문고본 +13 · 하나 초콜릿 +12 · 앨마 초콜릿 +9 · 니키타 캔커피 +8 …, 엑셀 `PX` 시트의 대원 열).
  - **친밀도 대화**: 친밀도 30·50·70·90 이 되면 새 대화가 해금되고 머리 위에 **♥**. 클릭해 대화하면 그 단계 대화가 나오고, 다 봤으면 해금된 가장 높은 단계 대화 (엑셀 `친밀도대화` 시트).
- **식당**: 시설 창에서 달러로 식재료 공급($20 → 12끼). 끼니마다 1끼 소모, 없으면 굶어서 피로 +.
- **저장**: 날짜가 바뀔 때·출전할 때·`저장` 버튼·타이틀로 갈 때 자동 저장 (`user://outgame_save.json`). 타이틀 `이어하기`로 불러옴.
- 스크린샷 확인: `--base_ui=supply:scrap=3,gunpowder=1` (창고에 넣고 납품 창) · `--base_ui=general:whiskey=2,…` (창고에 넣고 장군 점검 지금).
- **디버그 `F1`**: +1시간 · 다음 날/주/달 · 전리품 +2 · 점검 지금 · 달러 +100 · 전투 발생 · 대원별 상태·목적지·이유 · 이번 달 점검 예정 시각.
- **기지 데이터 = `data/outgame.xlsx`** (설정·층·시설·대원·의뢰·대사·대화이벤트·요청·제작 + 읽어보기). 시설 이름·대사·수치는 모두 **더미/임시값** — 엑셀에서 바꾸고 저장하면 실행 중인 게임에 1초 안에 반영.
- **대원 주간 일정 = Godot 에디터 상단 `일정` 탭** (`data/outgame/schedules/<대원 id>.json`): 7일 시간표, 블록(시작·끝·목적지·행동·해금 조건·잠기면 갈 곳),
  자주 머무는 장소, 청소 위임 성향, 시간 스크러버 미리보기(그 시각의 목적지·경로), 검사(경로 불가·겹침·잠긴 목적지·참조 누락), `기지 테스트 플레이`.

## 밸런스 데이터 (엑셀) · AI 에디터 · 스테이지 에디터
에디터는 Godot 에디터 플러그인(`addons/rtz_ai_editor`, `addons/rtz_stage_editor`, `addons/rtz_schedule_editor`, `addons/rtz_battle_editor`, `addons/rtz_sortie_editor`, `addons/rtz_skill_editor`, `addons/rtz_quest_editor`, `addons/rtz_cutscene_editor`)으로, `./play.sh edit` (Windows `play.bat edit`) 로 에디터를 열면 상단 탭에 `AI` · `스테이지` · `일정` · `전투 발생` · `출정 대사` · `스킬 트리` · `퀘스트` · `컷씬` · `스토리`(흐름 보기) 가 있습니다.
**모든 탭 공통: `Ctrl+Z` = 뒤로 감기 · `Ctrl+Y` (또는 `Ctrl+Shift+Z`) = 앞으로 감기** (Mac 은 Cmd, 탭마다 200단계, 글자를 이어 치면 한 단계로 묶임). 글자 칸에 커서가 있으면 그 칸 글자만 되돌리고, 칸 밖을 한 번 누르면 탭 전체 뒤로 감기. 파일을 다시 읽으면(`되돌리기` · 다른 파일/대원 열기) 기록은 새로 시작. 저장은 따로 (`Ctrl+S`).
**밸런스 수치는 `data/balance.xlsx`** 한 파일에 시트별로 있습니다: `캐릭터` · `몬스터` · `아이템` · `스킬` · `스테이지` (+ 열 설명 `읽어보기`).
- 엑셀(또는 Numbers·LibreOffice)로 열어 고치고 **저장하면 1초 안에 게임이 다시 읽어 바로 적용** — 진행 중인 전투의 HP·AP·위력·이름까지.
  캐릭터 추가·편성·적 배치처럼 전투 구성이 바뀌는 것은 다음 전투(R 재시작)부터.
- 열 이름(1행)으로 찾으므로 열 순서는 바꿔도 되고, 행을 추가하면 새 캐릭터·몬스터·스킬·스테이지가 됩니다. 다른 시트에서 쓰는 이름은 `id` 열.
- 잘못된 참조(없는 무기·스킬 id 등)는 전투 중 알림과 콘솔 경고로 알려줍니다.

**AI 에디터** (Godot 에디터 상단 `AI` 탭 — 2D · 3D · Script 옆): 몬스터 AI 를 노드로 연결해 만듭니다 → `data/ai/<이름>.json`.
- 노드: 시작 / 조건(이번 턴 행동 수·AP·HP·우리 편 HP·상대 수·스킬 사용 가능·처치 가능·확률 → 예/아니오) / 스킬 사용(스킬·대상 고르기, 안 되면 '실패 시') / 턴 종료.
- 행동 하나마다 시작부터 다시 평가. 저장(버튼 또는 Ctrl/Cmd+S)하면 실행 중인 게임에도 바로 반영.
- 엑셀에서 스킬·몬스터를 바꿨으면 오른쪽 위 `엑셀 다시 읽기`.
- 어떤 몬스터가 어떤 AI 를 쓸지는 엑셀 `몬스터` 시트의 `AI` 열. 기본 제공: `default`(구울·슬라임), `aggressive`(늑대).

**스테이지 에디터** (Godot 에디터 상단 `스테이지` 탭): 스테이지별 적 배치를 칸에 놓아 만듭니다 → `data/stages/<스테이지 id>.json`.
- 왼쪽에서 몬스터를 고르고 칸 클릭 = 배치(2칸 몬스터는 두 칸), 배치된 몬스터 클릭/우클릭 = 제거, 저장 → `테스트 플레이`(에디터에서 그 스테이지로 전투 실행, F8 로 종료).
- 스테이지 목록·이름·조명·선공·적 HP/공격 배율·시드는 엑셀 `스테이지` 시트 (행 추가 = 새 스테이지). 메뉴의 `스테이지` 에서 골라 플레이.

## 전투 HUD 위치 편집 (Godot 에디터)
전투 HUD 의 배치는 `scenes/battle_hud.tscn` 에 노드로 저장돼 있어 에디터에서 직접 보고 옮길 수 있습니다.
1. `./play.sh edit` (Windows `play.bat edit`) 로 에디터를 열고, 파일 시스템 창에서 `scenes/battle_hud.tscn` 더블클릭.
2. 씬 트리에서 노드를 골라 화면에서 끌어 옮기거나, 인스펙터 **Layout → Transform/Anchors** 의 위치·크기(offset)를 고칩니다.
3. `Ctrl+S`(맥 `Cmd+S`) 저장 → 게임 실행하면 바로 반영.

| 노드 | 화면 요소 |
|---|---|
| `TopBar/TopRow/RoundLabel` | 좌상단 "라운드 N" |
| `Timeline` | 상단 중앙 행동 순서 초상화 줄 (초상화는 실행 중에 채워짐, 에디터에선 빈 상자) |
| `LogButton` / `LogPanel` | 우상단 전투 기록 아이콘 / 펼친 기록 창 |
| `PresetLabel` | 조명 프리셋 안내 글자 |
| `Bottom` (`BottomRow` 안: `PortraitFrame`, `Info`, `Spacer`, `EndTurnWrap/EndTurn`) | 하단 패널 전체·초상화·이름/수치·턴 종료 |
| `SlotsRow` | 하단 가운데 무기·자리 이동·스킬·필살기 슬롯 줄 (실행 중에 채워짐) |
| `StatusWindow` | 상태 이상 창 |
| `ResultBanner`, `Toast`, `DebugPanel` | 승패 글자, 알림, F1 디버그 창 |

- 컨테이너(`BottomRow`, `Info` 등) 안의 노드는 컨테이너가 자리를 정하므로 직접 끌 수 없습니다. 순서(씬 트리에서 위/아래로 끌기), 최소 크기(`custom_minimum_size`),
  간격(Theme Overrides → Constants → separation)으로 조정합니다.
- 슬롯 하나하나의 크기(스킬 75px, 무기 44×112 등)·색은 `scripts/ui/battle_hud.gd` 상단 상수(`SLOT`, `WEAPON_W` …)에서 바꿉니다.
- `godot --headless --path . ++ --export_hud=1` 은 코드 기본값으로 `battle_hud.tscn` 을 **다시 만들어 편집한 배치를 덮어씁니다** (처음 생성용).
- 맥에서 배치를 고친 뒤 `git pull` 을 하면 충돌할 수 있으니, 고친 `battle_hud.tscn` 은 커밋하거나 알려 주세요.

## 카메라 (2D 전투)
2D 전투는 정면 평면이 아니라 **뒤로 물러나 40° 내려다보는 가상 카메라**로 구성됩니다. `tools/gen_sprites.py` 의 `CAMERA`
(피치 40°, 거리 15m, 세로 화각 32°, 화면 중심 y 480 — 벽이 더 보이고 바닥이 덜 보이게 구도를 위로)로 배경(바닥 원근·벽·소품·빛 영역 마스크)을 그리고, 같은 값이
`manifest.json` 의 `camera` 로 저장되어 `BattleView2D` 가 슬롯 위치와 캐릭터 크기(원근 배율)를 계산합니다.
각도나 거리를 바꾸려면 `CAMERA` 를 수정하고 `python3 tools/gen_sprites.py` 를 다시 실행하면 배경과 배치가 함께 바뀝니다.
배경 3D 방도 같은 각도(40°)로 맞춰 그립니다.

## 레벨 · 스킬 (액티브 · 패시브 · 신앙)
전투에 나간 대원은 **경험치**(승리 100 · 패배 40)를 받고, 레벨이 오를 때마다 **스킬 포인트 +1** (처음 1).
기지 위 **`스킬` 버튼**(또는 대원 우클릭 → 스킬 트리, 정보·장비 창)으로 **스킬 창**을 엽니다.
- **왼쪽 = 대원 목록** (초상화·레벨·남은 포인트, 위아래 스크롤 — 대원이 늘어나도 그대로). 누르면 그 대원으로 바뀜.
- **위 탭 = 스킬 종류 세 가지**
  - **액티브 스킬**: 전투에서 쓰는 스킬을 강화(강공격·기본 공격·필살기 위력 등)하고, **새 스킬**도 배움 (지금 데이터는 갈래 끝에서 강타·측면 기습·재정비·고무, 앨마는 강화만 — 기본 스킬 칸 3개가 이미 참).
  - **패시브 스킬**: 늘 적용되는 능력치(최대 HP·속도·AP·AP 회복·방어·모든 공격 위력·회복량).
  - **신앙 스킬**: 믿는 신에 따라 배울 수 있는 스킬이 다름 (아래).
- 액티브·패시브 트리 **모양은 캐릭터마다 자유** (지금 기본 데이터는 모두 십자형: 가운데 시작 → 화력·기동·생존·전술 네 갈래 × 3단계).
  규칙: **시작 노드**는 처음부터 배움 · **선을 따라 선행 스킬부터**(하나라도 / `모두` 표시면 전부) · **`택1`(택일 그룹)은 트리마다 그중 하나만** → 어느 쪽으로 뻗을지가 빌드. 스킬 포인트는 두 트리가 **같이 씀**. 색(갈래)은 보이기만.
- **레벨이 모자란 스킬은 회색 + 가운데 붉은 "경험 부족"**. 노드를 누르면 왼쪽에 설명·필요 레벨, `배우기`. `액티브/패시브 초기화` = 그 트리 포인트 돌려받기 (지금은 무료).
- 효과는 기지에서 출전한 전투에 반영. 레벨도 피해·회복에 반영(레벨/2).
- **스킬 노드는 직접 짬 = Godot 에디터 상단 `스킬 트리` 탭** (`data/skill_tree.json`):
  캐릭터·액티브/패시브 트리를 고르면 격자 위에 그 트리. **모양을 마음대로 짬**:
  **빈 칸 클릭 = 새 노드**(노드를 골라 둔 채면 그 노드에서 이어짐 — 선행 · 같은 색 · 필요 레벨 +2) · **노드 끌기 = 옮기기** · **Shift+클릭 = 고른 노드 → 누른 노드 선 잇기/끊기** · **Delete = 삭제**(뒤 노드는 선행을 이어받음).
  **`모양 틀`** = 십자형 · 두 갈래(Y자) · 일자(사다리) · 나무(줄기+세 가지) · 그물(갈라졌다 합류) 빈 노드로 새로 짜기. `다른 캐릭터 트리 가져오기` = 모양째 복사.
  노드를 누르면 오른쪽에서 이름 · **갈래(색)** · **시작 노드** · 필요 레벨 · **선행**(추가·✕, 둘 이상이면 `모두 필요`) · **택일 그룹**(같은 이름끼리 하나만) · 효과 · 값 · 설명 · 옮기기(←↑↓→).
  효과 = 최대 HP · 속도 · 최대 AP · AP 회복 · 방어 · 모든 공격 위력 · 모든 회복량 · **스킬 강화**(고른 스킬 위력·회복·AP 지급 +) · **새 스킬**(스킬 시트에서 고름). 설명은 `설명 자동 채우기` (효과·값을 바꾸면 같이 바뀜).
  `필요 레벨 자동`(시작 노드에서 선을 따라 몇 번째인지로 시작 +0/+2/+4…) · `트리 비우기`.
  아래 **검사**: 겹친 id · 같은 칸 · 없는 선행 · 돌고 도는 선행 · 없는 스킬(오류) / 필요 레벨이 선행보다 낮음 · 하나뿐인 택일 그룹 · 새 스킬이 기본 스킬 칸(3칸)을 넘을 수 있음(주의).
  옛 십자형 파일도 읽으면 같은 모양으로 바뀜 (저장 파일의 배운 스킬 그대로). 저장(Ctrl/Cmd+S) → 게임 실행 중이면 바로 반영. `기지 스킬 창 테스트 플레이` = 그 대원을 정한 레벨로 올려 기지 스킬 창.
- 새 스킬 자체(AP·위력 등)는 밸런스 엑셀 `스킬` 시트. 경험치·레벨 수치는 기지 엑셀 `설정`(xp_win, xp_lose, xp_level_base, xp_level_step, level_max).
- 전투 결과 화면에 출전 대원 경험치·레벨 업 표시.
- 확인: `godot --path . ++ --scene=base --base_ui=skills:a_dan:2500:dan_a_n1,dan_a_n2,dan_a_n3::active` (경험치 주고 배운 상태로 창, 셋째 칸 `L9` = 레벨 9 까지, 마지막 칸 active / passive / faith).

- **신앙 스킬**: 캐릭터마다 **믿는 신**이 있고, **신에 따라 배울 수 있는 신앙 스킬이 다름**. 신앙도(0~100)가 필요치 이상이면 포인트 없이 배움, 모자라면 회색 + 붉은 "신앙 부족". 아래에 다른 신들의 스킬(배울 수 없음)도 표시.
  **신앙도는 퀘스트 · 대화 · 이벤트로만 오름** (전투 출전으로는 안 오름 — 기지 엑셀 설정 `faith_battle` 은 이제 안 씀): 퀘스트 보상 `신앙도`(받는 대원 = 의뢰인 또는 고른 대원) · 컷씬 행동 `대원 신앙도 +/-` · 요청 수락(엑셀 `요청` 시트 `수락효과` 에 `신앙:5` — 여러 개는 `의뢰:c_ext_escort, 신앙:5` 처럼 `,`).
  **믿는 신이 없는 대원(무신앙)도 가능**: 신앙 탭에 **"믿음이 없습니다."** · 신앙 스킬은 비어 있고 · 신앙도가 쌓이지 않음 (보상을 받아도 '믿음이 없어 안 쌓임'). 에디터 `대원 신앙` 에서 `무신앙` 을 고르면 됨.
  **신·신앙 스킬 = Godot 에디터 `스킬 트리` 탭 → `신앙 스킬`** (`data/faith.json`): 왼쪽 신 목록(추가·삭제, id·이름·상징색·설명, 믿는 대원 표시) · 가운데 그 신의 신앙 스킬(필요 신앙도 순, 추가·삭제) · 오른쪽 id·이름·필요 신앙도·효과·값·설명(자동 채우기) · 아래 검사.
  **누가 어느 신을 믿는지(무신앙 포함)·시작 신앙도도 같은 화면 아래 `대원 신앙`** (대원마다 믿는 신 고르기 — 무신앙 포함 · 시작 신앙도, `data/faith.json` 의 `believers`). 엑셀 캐릭터 시트의 `신`·`신앙` 열은 없앰.
  신마다 **아이콘 글자**(비우면 이름 끝 단어 첫 글자: 솔·베·녹·테) — 게임에서 상징색 원 아이콘. **`아이콘 그림`** 을 고르면 글자 대신 그 그림(상징색 테두리 고리 안에): `assets/gods/` 의 PNG 목록에서 고르거나 **`그림 가져오기…`**(PC 의 그림을 `assets/gods/<신 id>.png` 로 복사). 정사각형 · 투명 배경 PNG 권장. 신 목록·스킬 창 신앙 탭·도감·대원 정보 등 신 아이콘이 나오는 곳 모두. 신 id 를 바꾸거나 지우면 믿는 대원도 따라감(지우면 무신앙). **지금 값은 임시** (태양신 솔루스·전쟁신 베이라·밤의 여신 녹트·대지모 테라, 각 4개).
  게임 스킬 창 신앙 탭·대원 정보 카드의 **신 아이콘을 누르면 세계관 도감 `종교(신)` 탭**의 그 신.
- **신 해금 캐릭터 → 기적**: 정체가 신인 캐릭터가 있음. **해금되면 그 캐릭터의 스킬 창 신앙 탭이 `✦ 기적`** 으로 바뀜 — 정체인 신(아이콘 → 도감), 신앙도 대신 **의지**(해금될 때 `시작 의지`, 출전마다 + 기지 설정 `will_battle`(기본 5) — 신앙도를 올려도 기적에는 안 씀), 그 캐릭터만의 **기적**(필요 의지 이상이면 포인트 없이 배움, 모자라면 회색 + '의지 부족'). 전에 배운 신앙 스킬 효과는 그대로. 대원 목록·도감에 ✦, 도감 등장인물에 '정체' 표시(잠긴 동안은 안 보임).
  **에디터 `스킬 트리` 탭 → `기적 (신 해금)`** (`data/faith.json` 의 `divine` · `miracles`): 왼쪽 대원 목록에서 고르고 **`이 캐릭터는 정체가 신`** 을 켜면 신 해금 캐릭터 → 정체인 신 · **`이미 해금됨 (처음부터 신)`** 체크 · 체크 안 하면 **해금 조건**(직접 해금 = 이벤트·대사 / **미션 완료** = 고른 의뢰 업무를 끝냄·고른 전투 승리·고른 연구 완료·고른 **퀘스트** 완료 / 레벨 / 신앙도 / 친밀도 / n일차 + 값) · "새 게임: 잠김 → …" 확인 줄. 가운데 그 캐릭터의 기적(추가·삭제), + **시작 의지**. 오른쪽 기적 id·이름·필요 의지·효과·값·설명. 테스트 플레이 = 정체 해금 + 의지 100 으로 기적 탭.
  게임에서 상태 확인: `BaseSim.divine_state(캐릭터)` = `""`(신 아님) / `"locked"` / `"unlocked"`, 직접 해금 `BaseSim.unlock_divine(캐릭터)`. 조건은 미션(의뢰·전투·연구·퀘스트)을 끝낼 때·레벨·신앙도·친밀도가 바뀔 때·날이 바뀔 때·불러온 뒤 검사 → 해금되면 기록·알림. 미션 완료 확인 `BaseSim.quest_done("quest:q_hana_secret")`. 확인: `--base_ui=divine:a_hana:30` (셋째 칸 = 더할 의지).
  **하나 = 신 (잠김)** — 미션 완료로 해금. **[임시]** 정체 = 대지모 테라, 미션 = **퀘스트 '하나의 비밀'** 완료(아래 '퀘스트'), 시작 의지 10, 기적 3개 (대지의 맥박 의지 20 · 흔들리지 않는 자 40 · 대지모의 현신 70). 니키타는 신 아님.
  확인: `godot --path . ++ --scene=base --base_ui=faith:a_dan:15:veyra_1`

- **스킬 표 = `data/skills.xlsx` (엑셀로 수치 밸런스)**: 스킬 트리 · 신 · 신앙 스킬 · 믿는 신 · 신 해금 · 기적 · 스킬 상태 이상 · 상태 정의 · 몬스터 스킬 · 스킬 포즈의 **수치 · 이름 · 설명 · 효과**를 엑셀에서 고치고 저장하면 **바로 적용** — 실행 중인 게임은 1초 안에 다시 읽고, 에디터 `스킬 트리` 탭도 1초 안에 읽어 화면에 반영 (저장 안 한 다른 편집은 그대로, Ctrl+Z = 표 읽기 전으로).
  - **표가 원본**: 게임 · 에디터가 JSON 을 읽은 뒤 표의 값을 덮어씀. 에디터에서 저장하면 표도 같이 다시 써짐 (**엑셀에 열어 둔 채 에디터 저장 = 실패, 아무것도 저장 안 됨** → 엑셀 닫고 다시 저장. 표에 직접 넣은 서식 · 수식은 그때 사라짐).
  - 고칠 수 있는 열 = 머리 줄이 진한 열 / `(참고)` 열(회색) = 보기용, 고쳐도 무시. 줄은 `… id` 열로 찾음 (id 는 바꾸지 말 것, 열 순서 바꾸기 · 메모 열 추가는 됨). 숫자 칸을 비우면 원래 값 그대로.
  - **추가 · 삭제 · 선행 잇기 · 트리 모양은 에디터에서** (표에 새 id 줄을 넣어도 무시). 에디터 밖에서 JSON 을 고친 뒤 표를 새로 맞추려면 `godot --headless --path . -s tools/skill_table.gd`.
  - 전투 스킬 수치(AP · 위력 · 대상)는 그대로 `data/balance.xlsx` `스킬` 시트. 코드 = `scripts/data/skill_table.gd` (SkillTable) · `scripts/data/xlsx_writer.gd`.
  - 내 컴퓨터에서 표를 고친 채 `git pull` 이 이 파일 때문에 멈추면: 고친 걸 먼저 커밋 · 푸시하거나, 버려도 되면 `git checkout -- data/skills.xlsx` 뒤 다시.

## 퀘스트 (에디터)
- 게임: 기지 상단 **`퀘스트`** 버튼 → 퀘스트 창 (진행 중 → 완료, 시작 안 한 퀘스트는 안 보임). 카드마다 의뢰인 얼굴 · 설명 · 단계(✓ 끝냄 / ▶ 지금 + 진행 횟수 / 뒤 단계는 `???`) · 보상. 시작·다음 단계·완료 때 알림, 기지 기록에 `◆`.
- 규칙(`BaseSim`): **시작 조건**을 채우면 자동 시작 (처음부터 / 직접 시작 = 이벤트·대사에서 `BaseSim.start_quest(id)` / 미션 완료 후(의뢰·전투·연구·다른 퀘스트) / 의뢰인 레벨·신앙도·친밀도 / n일차) → **단계를 앞에서부터 하나씩** → 마지막 단계를 끝내면 완료 + **보상**(현금은 주간 결산 때, 친밀도는 의뢰인).
  단계 종류: 의뢰 완료 · 전투 승리(스테이지 또는 아무 전투) · 대원과 대화 · 연구 완료 · 대원 친밀도 · 대원 레벨 · 일차 도달 · 다른 퀘스트 완료 · 컷씬 보기. **횟수 단계(의뢰·전투·대화)는 그 단계가 시작된 뒤부터 셈** — 전에 한 것은 안 셈.
  완료한 퀘스트는 **신 해금 조건 `미션 완료 → 퀘스트`** 로 씀 (`quest:퀘스트 id`). 저장 파일에 진행 단계·대화 횟수 저장.
- **에디터 = Godot 에디터 상단 `퀘스트` 탭** (`addons/rtz_quest_editor` → `data/quests.json`):
  왼쪽 퀘스트 목록(추가 · 복제 · 삭제 · ↑↓ 순서, ✦ = 신 해금에 쓰임) · 가운데 id(바꾸면 다른 퀘스트·신 해금 조건도 따라감) · 이름 · 의뢰인 · 설명 · 시작 조건 · **단계 카드**(종류 · 대상 · 횟수/값 · 표시 글 — 비우면 자동 설명, ↑↓ · 삭제) · 보상(현금 · 의뢰인 친밀도 · **신앙도** + 받는 대원).
  오른쪽 **게임 퀘스트 창 미리보기** · 연결(이 퀘스트로 해금되는 신 · 이 퀘스트를 쓰는 퀘스트 · **`이 퀘스트로 신 해금`** = 신 해금 캐릭터의 해금 조건을 이 퀘스트 완료로 → `faith.json`) · 검사(없는 대상 · 중복 id · 의뢰인 없는 조건 등).
  **`기지 테스트 플레이`** = 저장 → 새 기지에서 그 퀘스트를 시작(`시작 단계` 까지 건너뛰기)하고 퀘스트 창. 저장하면 게임 실행 중에도 다시 읽음.

## 컷씬 (에디터)
- 게임: 대화 장면 · 이미지 CG 를 보는 재생 화면 (기지 위에 덮어서, 그동안 시간 멈춤). **대사** = 말하는 대원이 왼쪽/오른쪽에 서고(말하는 쪽 밝게) 아래 상자에 이름·글이 한 글자씩 · **나레이션** · **CG**(화면 전체 그림 — 'CG 끄기'·배경 컷까지 대사가 그 위에) · **배경**(없으면 기지 화면이 어둡게 비침) · **선택지** · **행동**(퀘스트 시작 · 신 정체 해금 · 친밀도 · 신앙도 · 현금).
  클릭 · Space · Enter = 다음 (글이 나오는 중이면 다 보이기) · Esc / `건너뛰기` = 끝까지 (행동은 그대로 적용).
- **이어지기**: 컷씬이 끝나면 `다음 컷씬` 으로, 선택지는 고른 것의 컷씬으로 (끝 = 그 컷씬 다음 컷). 대화 → 이벤트 → 퀘스트 → 오프닝 어느 컷씬끼리도 이어 붙일 수 있음.
- **계기(언제 나오나)**: 새 게임 시작(오프닝) · 퀘스트 시작 / n단계 시작 / 완료 · 지휘관이 대원에게 말 걸기(평소 대사 대신) · 대원끼리 대화 엿듣기(엿듣기 창 대신) · n일차 아침 · 신의 정체가 드러날 때 · 전투 승리 · 없음(이어지기·직접 재생만, 스크립트 `BaseSim.queue_cutscene(id)`). `한 번만` 체크. 같은 때 여러 개면 목록 순서대로 하나씩, 창이 열려 있으면 닫힌 뒤.
  본 컷씬은 저장되고, 퀘스트 단계 `컷씬 보기` · 미션 `cutscene:id`(퀘스트 시작 조건 · 신 해금 조건)로 쓸 수 있음.
- **에디터 = Godot 에디터 상단 `컷씬` 탭** (`addons/rtz_cutscene_editor` → `data/cutscenes.json`, 그림은 `assets/cg/`):
  왼쪽 목록(분류 오프닝·대화·이벤트·퀘스트·기타로 거르기 · 추가 · 복제 · 삭제 · 순서, ▶ = 계기 있음 · ↪ = 이어짐) · 가운데 id(바꾸면 이어지는 곳도 따라감) · 이름 · 분류 · 계기 · 한 번만 · 다음 컷씬(**`새 컷씬 만들어 잇기`**) · **컷 카드**(종류별 칸 — 대사: 대원·표시 이름(예: ???, 테라)·서는 곳·**포즈**(기본 그림 / 그 대원의 상황별 포즈 그림) / CG·배경: 그림 고르기 + 썸네일 / 선택지: 선택지마다 이어질 컷씬 + `새 컷씬` / 행동, ↑↓ · 복제 · 삭제, 아래 버튼 = 고른 컷 다음에 추가).
  오른쪽 **게임과 같은 재생 화면 미리보기**(카드 클릭 = 그 컷, **`▶ 이 컷부터 미리보기 재생`** 뒤 미리보기 클릭 = 다음, 선택지·이어지기도 그대로) · 흐름(계기 · 어디서 이어져 오는지 · 어디로 가는지 · 쓰는 퀘스트, 눌러서 이동) · 검사(없는 컷씬·대원·그림·퀘스트, 선택지 없음 등).
  **`기지 테스트 플레이 (이 컷부터)`** = 저장 → 새 기지에서 그 컷부터 재생. 새 CG 는 `assets/cg/` 에 PNG 를 넣고 탭을 다시 열면 목록에 나옴(임포트 안 기다려도 보임).
- **[임시] 컷씬 9개**: 오프닝(무너진 도시 CG → 기지 복도, 단·키라·앨마 → 이어서 혼자 있는 하나 → 선택지 '말을 건다' → 하나 컷씬) · 하나의 비밀 완료 → 대지모의 현신(CG) · 로한의 첫 연구 시작 → 연구실 · 3일차 → 옥상의 밤(키라·니키타, 친밀도 +3) · 단에게 처음 말 걸기 → 단의 조언(선택지 2갈래). 그림 4장은 자리표시.
- **대사 포즈**: 대사 컷마다 `포즈` — 기본 그림 대신 그 캐릭터의 상황별 그림(니키타: 공격 shot · 버프·스킬 point_up · 피격 hit · 회피 miss · 기절 stun · 지침 tired · 쓰러짐 dead · 언짢음 annoying). 기본 그림과 같은 배율 · 같은 발 위치에 섬, 그 대원이 다시 말할 때까지 그 포즈 유지. [임시] 옥상의 밤 니키타 마지막 대사 = miss(여유 있는 표정).
- 확인: `godot --path . ++ --scene=base --base_ui=cutscene:cs_opening` (셋째 칸 = 시작 컷 번호, 0부터). 테스트 플레이·스크린샷(`--base_ui`·`--shot`)에서는 오프닝 등 대기 컷씬이 안 나옴.

## 스토리 흐름 (에디터)
**Godot 에디터 상단 `스토리` 탭** (`addons/rtz_story_editor`): 퀘스트 · 컷씬 · 신 정체 해금 · 미션(의뢰·전투·연구) · 계기(새 게임 · n일차 · 말 걸기 · 엿듣기 · 전투 승리)가 **어떻게 이어지는지 한 그림으로** — 그리고 **그 그림에서 바로 선을 긋고 고침**.
- **왼쪽이 먼저, 오른쪽이 나중** (열 = 계기에서 몇 단계 뒤인지). 선 위 글 = 어떻게 이어지는지: `시작` · `n단계` · `완료 후 시작` · `시작 때 / n단계 시작 때 / 완료 때`(퀘스트 → 계기 컷씬) · `다음` · `선택: …` · `퀘스트 시작` · `정체 해금` · `완료 후 해금`.
- 노드 색: 퀘스트(주황, 단계·보상) · 컷씬(파랑, 분류·대사 수·행동) · 신 정체 해금(보라) · 미션(초록) · 계기(회색). 위 `보기` 체크로 종류를 숨김.
- **선 긋기 = Shift 를 누른 채 노드를 끌어 다른 노드에 놓기** → 무슨 뜻으로 이을지 고르는 창 (하나뿐이면 바로). 이을 수 있는 짝과 뜻:
  - 계기 → 퀘스트: 처음부터 / 직접 / n일차부터 시작 · 계기 → 컷씬: 새 게임(오프닝) / n일차 아침 / 말 걸기 / 엿듣기 / 전투 승리 때 재생 · 계기 → 신 해금: 처음부터 / 직접 / n일차.
  - 퀘스트 → 퀘스트: 완료 후 시작 / 단계에 "그 퀘스트 완료" 추가 · 퀘스트 → 컷씬: 시작 때 / 1단계 시작 때 / 완료 때 재생 · 퀘스트 → 신 해금: 완료 후 해금.
  - 컷씬 → 컷씬: 다음 / 선택지(선택지 컷이 없으면 만들고 선택지 하나 추가) · 컷씬 → 퀘스트: 끝에 행동 '퀘스트 시작' / 본 뒤 시작 조건 / 단계에 "컷씬 보기" 추가 · 컷씬 → 신 해금: 행동 / 해금 조건.
  - 미션 → 퀘스트: 완료 후 시작 / 단계 추가 · 미션 → 신 해금: 해금 조건.
- **선 지우기 = 선 클릭 → Delete** (오른쪽에 그 선이 데이터 어디인지와 지우면 어떻게 되는지): 시작 조건 → 직접, 계기 → 없음, 다음 → 비움, 선택지 → 끝, 행동·단계 → 삭제, 해금 조건 → 직접.
- `+ 퀘스트` · `+ 컷씬`(새 노드, 이름 · 의뢰인 · 분류 · 한 번만은 오른쪽에서 바로) · `+ 계기 ▾`(새 게임 · n일차 · 말 걸기 · 엿듣기 · 전투 승리 · 처음부터 · 직접 — 이어 주기 전까지는 임시 노드).
- 퀘스트 · 컷씬 · 신 해금 노드 고르고 **Delete = 그래프에서 빼기** — 다른 노드와의 선만 끊고 **데이터는 그대로**(퀘스트 · 컷씬 탭에는 남음, 미션 단계 같은 자기 내용도 그대로). `꺼내기 ▾` 로 언제든 다시 그래프에 올려 Shift 끌기로 이음. 다른 탭에서 그 퀘스트를 어딘가에 이어 주면 저절로 다시 보임. (뺀 목록은 `story_layout.json`.) 미션 노드는 퀘스트 단계가 쓰는 동안 보임.
- 노드 끌기 = 자리 옮기기(`data/story_layout.json` 에 저장, `자동 배치` 로 되돌림) · 빈 곳 끌기 = 화면 옮기기 · 휠 = 확대 · `전체 보기` · 더블클릭 / `그 탭에서 열기` = 퀘스트 · 컷씬 · 스킬 트리(기적) 탭으로 (단계 · 대사 · 보상 같은 세부는 거기서; 저장 안 한 편집은 먼저 저장).
- **저장 (Ctrl+S)** = `data/quests.json` · `cutscenes.json` · `faith.json`(divine) · `story_layout.json`. Ctrl+Z / Ctrl+Y 되돌리기 · 다시 하기, `되돌리기` = 파일대로. **다른 탭에 갔다 와도 편집 · 되돌리기 기록 · 고른 것 유지** (파일이 그대로면 다시 읽지 않음; 다른 탭에서 저장해 파일이 바뀌었으면 — 여기 편집이 없을 때만 새로 읽고 Ctrl+Z 로 읽기 전으로 갈 수 있음, 편집 중이면 그대로 두고 알림).
- 검사: 없는 퀘스트·컷씬·캐릭터를 가리킴(오류) · 직접 시작 퀘스트인데 아무 컷씬도 시작 안 함 · 계기 없는 컷씬이 어디서도 안 이어짐 · 직접 해금인데 해금하는 컷씬 없음 · 되돌아가는 흐름(순환).
- 규칙 코드 = `scripts/data/story_graph.gd` (StoryGraph, 선마다 데이터 어디서 왔는지 `src`) + `scripts/data/story_edit.gd` (StoryEdit — 선 긋기 뜻 목록 · 적용 · 지우기 · 노드 추가 · 삭제, 헤드리스 테스트 `[13h]`).

## 세계관 도감
기지 상단 **`도감`** 버튼 (또는 신 아이콘 클릭). 탭 = **등장인물 · 몬스터 · 상태이상 · 종교(신) · 도시 배경**. 왼쪽 목록(위아래 스크롤) → 오른쪽 그림·이름·부제·설명 + 게임 기록.
- 등장인물: 아군 + 전투에 안 나가는 대원(로한) — 병과·레벨·키·HP·속도·AP·방어·사거리, **믿는 신 아이콘(누르면 그 신)**.
- 몬스터: 레벨·HP·속도·AP·방어·차지 칸·쓰는 기술. 상태이상: 효과(긍정/부정)·규칙·그 상태를 거는 기술. 종교(신): 설명·**믿는 대원(누르면 그 대원)**·신앙 스킬. 도시 배경: 설명만.
- **데이터 = `data/codex.json`** — 탭마다 `{id, title, subtitle, body}` (등장인물 `sprite`, 도시 `color`). 등장인물·몬스터·상태이상·신은 게임 데이터(엑셀·statuses.json·faith.json)에 있는 것이 자동으로 들어가고 이 파일은 설명·부제·순서만 덧붙임 (제목을 비우면 게임 이름, 설명이 없으면 "기록 없음"). 도시 배경은 이 파일에만.
- **지금 설명은 모두 임의로 넣은 `[임시]`** (도시: 헤이븐 기지 · 잿빛 항구 애시포트 · 옛 수도 칼드라 · 하층 구역).
- 확인: `--scene=base --base_ui=codex:gods:solus` (탭: characters · monsters · statuses · gods · cities).

## 상황별 포즈 그림 (전투 · 컷씬)
캐릭터마다 상황별 한 장 그림을 넣으면 전투와 컷씬 대사에서 씁니다. 지금은 **니키타**(`nikita_army`) 12장 (… · shot_pistol(자동권총 — 권총을 들 때) · annoying_2(주먹 쥐고 화남 — 팔짱과 무작위) · point_up_2(붕대 들기 — 가리키기와 무작위) · smirk(턱 괴고 웃음 — 대화용)) · **앨마**(`alma`) 12장 (shot(권총) · shot_2(리볼버 — 사격 때 무작위) · slash(나이프) · point_up(무릎 꿇고 붕대 — 회복·버프) · miss(몸 틀어 피함) · stun(이마 짚음) · hit(팔 감싸며 움찔) · annoying(팔짱 · 찡그림) · dead · smile(뒷짐 미소 — 대화용) · smile_2(팔짱 미소 — 대화용) · smirk(팔짱 · 음흉한 웃음 — 대화용)) · **단**(`dan`) 9장 (hit(뒤로 휘청) · dead · slash(나이프 — 지금 무기 도끼로 근접 공격할 때도 이 그림) · slash_2(주먹 — 나이프와 무작위) · miss(몸 낮춰 피함) · stun(머리 짚음) · tired(무릎 짚고 헐떡임) · annoying(주먹 쥐고 화남) · smile(허리에 손 · 크게 웃음 — 대화용)) · **하나**(`hero2`) 12장 (hit · hit_2 · miss · shot(저격총) · slash(대검) · tired · dead · point_up(주먹 자세) · stun(이마 짚음) · annoying(얼굴 가림) · move(총 들고 이동) · awkward(목 뒤 — 대화용) · shot_pistol(권총 — 권총을 들 때)) · **키라**(`kira`) 11장 (hit · hit_2 · miss · stun · slash(단검) · tired · annoying(앉아서 외면) · shot(소총) · shot_pistol(권총) · point_up(관자놀이 — 생각) · dead) · **이선**(`ethan`) 9장 (dead · hit · tired · slash(대검) · shot(소총) · shot_pistol(권총) · miss(움찔 피함) · stun(머리 짚음) · annoying(주먹 쥐고 분함)) (원본 = `art_src/<캐릭터>/`):

| 포즈 | 이름 | 전투에서 쓰는 때 |
|---|---|---|
| `shot` | 공격 | 적에게 쓰는 피해·상태 스킬 (자동) |
| `slash` | 근접 공격 | 근접 무기(대검 등)를 들고 공격 (자동, 그림이 없으면 shot) |
| `point_up` | 버프·스킬 | 회복·AP·버프 등 그 밖의 스킬 (자동) |
| `hit` | 피격 | 공격에 맞음 |
| `miss` | 회피 | 공격을 피함 |
| `stun` | 기절 | 기절이 걸림 |
| `tired` | 지침 | 디버프(부정 상태 이상 — 출혈·감속·구속 등)가 걸림 · **AP 를 다 씀(탈진)** |
| `dead` | 쓰러짐 | 쓰러짐 (그대로 남음, **회색 처리 · 쓰러지는 회전 없음**) |
| `annoying` | 언짢음 | **패배** — 결과 화면 오른쪽에 출전 대원 그림 |
| `move` | 자리 이동 | 자리 이동 · 자리 교체할 때 (이동을 기다리지 않음) |
| `awkward` | 머쓱함 | 대화용 (전투에서 자동으로 안 씀 — 스킬 포즈로 고를 수는 있음) |
| `smile` | 미소 | 대화용 (전투에서 자동으로 안 씀 — 스킬 포즈로 고를 수는 있음) |
| `smirk` | 음흉한 웃음 | 대화용 (전투에서 자동으로 안 씀 — 스킬 포즈로 고를 수는 있음) |

- 넣기: `python3 tools/char_sprites.py poses nikita_army dead=… hit=… miss=… shot=… stun=… point_up=… tired=… annoying=… --ref miss` → `<포즈>/0001.png` + 조명·선화·눈 마스크 + `anim.json {"pose": true}`.
  **무기별 그림** = `<포즈>_<무기 스프라이트>` (예: 키라 `shot_pistol`) — 그 무기를 들고 쓸 때 먼저, 없으면 `<포즈>`. 무기 스프라이트 = 엑셀 아이템 시트 `스프라이트` 열 (pistol · rifle · sniper · knife · bayonet …).
  **같은 포즈의 다른 그림** = `<포즈>_2`, `_3` … (예: 하나 `hit_2`) — 그 상황마다 무작위로 하나. 컷씬에서는 따로 고를 수 있음.
  하나: `python3 tools/char_sprites.py poses hero2 hit=… miss=… shot=…@fit slash=… tired=… dead=… point_up=… stun=… annoying=… awkward=… hit_2=… move=… --ref hit --band 0.25` · 키라: `… poses kira stun=… miss=… hit=… slash=… tired=… "annoying=앉은.webp*0.785" shot=소총.webp@fit shot_pistol=… --ref miss --band 0.25` · 이선: `… poses ethan dead=… hit=… tired=… slash=… shot=…@fit shot_pistol=…@fit miss=… stun=… annoying=… --ref slash --band 0.25` (`그림*배율` = 다른 크기로 그려진 그림을 모자 폭으로 맞춤 · `그림@fit` = 서 있는데 작게 그려진 그림의 키를 기본 그림 키에) (`--band` = 아래 25% 줄의 좌우 끝 가운데를 발로 — 한 발을 앞으로 뻗은 자세도 몸 가운데에).
  **크기 확인**: `python3 tools/char_sprites.py posecheck <캐릭터> [출력.jpg]` — idle · 걷기 · 뛰기 · 모든 포즈를 게임과 같은 배율 · 같은 발 위치로 한 장에 (초록 선 = 기본 그림 키). 지금 모든 캐릭터가 기본 그림과 키 ±2% · 눈 사이 폭 ±4% 안 ([니키타](docs/screenshots/posecheck_nikita_army.jpg) · [앨마](docs/screenshots/posecheck_alma.jpg) · [단](docs/screenshots/posecheck_dan.jpg) · [하나](docs/screenshots/posecheck_hero2.jpg) · [키라](docs/screenshots/posecheck_kira.jpg) · [이선](docs/screenshots/posecheck_ethan.jpg)). 전투에서 포즈가 보일 때 크게 보이는 것은 카메라 줌(1.5배, View 인스펙터 `포즈 연출`) — 줌 없이 보기 `--pose_zoom=1`.
  모든 포즈 같은 배율(`--ref` 그림의 키 = 기본 그림 키), 발 = 선 자세는 발 가운데 · 누운 그림(가로가 긴 그림)은 가운데 아래. 새 이름의 포즈도 그대로 넣으면 에디터 목록에 나옴. 그림이 없는 캐릭터는 예전 연출 그대로.
- **스킬마다 쓰는 쪽 포즈 = Godot 에디터 `스킬 트리` 탭 → `스킬 포즈`** (`data/skill_poses.json`): 스킬 목록(→ 지금 포즈) · `이 스킬을 쓸 때 포즈`(**자동** · **포즈 없음**(예전 공격 동작) · 포즈 이름) · 캐릭터별 미리보기 · 오른쪽 캐릭터별 포즈 그림 모음. 맞는 쪽 포즈는 상황으로 자동 (위 표).
- **캐릭터 · 무기별 공격 그림 = 같은 화면 오른쪽 `<캐릭터> 의 무기별 공격 포즈`** (`skill_poses.json` → `weapons`): 캐릭터를 고르면 그 캐릭터의 무기(엑셀 `무기` 열)마다 공격할 때 쓸 그림을 고름 — **자동**(그 무기 이름 그림 `shot_pistol` 같은 것이 있으면 그것, 없으면 원거리 shot / 근접 slash — 실제로 쓰일 그림을 함께 표시) 또는 그 캐릭터에게 있는 아무 포즈. 그 무기를 들고 적에게 공격·상태 스킬을 쓸 때 적용. 우선순위: 스킬에 정한 포즈 → 무기별 포즈 → 자동. 그림이 없는 포즈를 고르면 검사 오류.
  맞는 쪽 우선순위: 피함 miss → 기절 stun → 디버프 tired → 피해 hit (그 캐릭터에게 그림이 없으면 다음 후보). 넉백·끌어당김(즉시 효과)은 디버프로 안 침.
- **자리 이동 클릭**: 자리 이동 중에는 발밑 파란 표시뿐 아니라 **교체할 대원의 몸을 클릭해도** 그 자리와 바꿈 (바꿀 수 없는 대원은 안내, 자기 자신 클릭 = 취소). ![자리 이동 — 대원 몸 클릭](docs/screenshots/battle_move_click.jpg)
- **전투 연출 (카메라)**: 잠깐 바꾸는 포즈는 **카메라가 그 캐릭터 가운데로 빠르게(0.15초) 1.5배 줌** (캐릭터 가운데가 아래 HUD 위 화면 가운데쯤 `pose_screen_y` 290px 에 오게) — 캐릭터 크기는 그대로. 처음엔 캐릭터가 화면 가운데보다 **x −5px**(뒤쪽 — 적에게서 먼 쪽)에 있다가 **1.5초 동안 천천히 가운데로** → 끝나면 카메라가 움직이지 않고 **바로 원래 화면**, 캐릭터는 **idle**.
  줌해도 원래 화면 밖(방 바깥 빈 곳)은 안 보이게 — 화면 가장자리 캐릭터는 가운데까지 오지 않음 (`pose_keep_in_view`). 한 행동에 카메라는 한 캐릭터: 쓰는 쪽 포즈가 먼저, 없으면 맞는 쪽.
  **그림자도 그림 모양**: 포즈 그림이 보이는 동안 3D 배경의 그림자 판을 그 그림(알파)으로 바꿈 → 총·칼·뻗은 팔까지 그림자에. 쓰러진 그림(dead)은 판을 바닥에 눕혀 몸 아래 그림자로 남김 (그림이 없는 캐릭터는 예전처럼 쓰러지면 그림자 없음).
  `shot` · `slash` · `hit` 때 처음 **0.2초 카메라 흔들림** (한 행동에 한 번, 줌과 함께). 쓰러지는 공격을 맞으면 hit 없이 바로 dead. AP 를 다 쓴 행동은 그 포즈 뒤에 tired. 차례 시작 상태 이상 피해(출혈 등)는 포즈 없이 예전처럼 흔들림만.
  수치 조절 = `battle_2d.tscn` → View 노드 인스펙터 **`포즈 연출`**: 카메라 줌 배율(1.5) · 캐릭터가 올 화면 높이 · 줌 시간 · 보여 주는 시간 · 처음 가로 어긋남 · 돌아오는 시간(0 = 바로) · 화면 밖 안 보이기 · 흔들림 시간 · 세기.
  확인: `godot --path . ++ --scene=battle --ambush=ally --autoplay=pose:shot` (`slash` · `point_up` · `hit` · `miss` · `stun` · `tired` · `dead`, 캐릭터 고르기 `--pose_char=hero2`) · 패배 화면 `--scene=result --winner=enemy`.
- **컷씬**: 대사 컷의 `포즈` — 8장 모두 고를 수 있음 (컷씬 항목).

## 기지 대원 조명 · 그림자 (실시간)
기지 대원은 방 프리셋 색을 한 번에 입는 게 아니라 **지금 서 있는 자리에 실제로 닿는 방 스폿 조명**으로 매 프레임 칠합니다 (`BaseView3D.light_probe` → `NpcView`).
- 빛을 받는 쪽·그림자 면·림이 조명 위치에 따라 정해지고, 걸어서 조명 아래를 지나면 밝기·색·빛 방향이 **따라 바뀜** (0.25초쯤에 걸쳐 섞여서 깜빡이지 않음). 조명 원뿔 밖(방 구석·꺼진 방)은 주변광만.
- 가장 센 조명 = 주조명(빛 쪽 면 색). **림(빛 반대쪽 가장자리 선)은 항상** — 반대쪽에서 오는 두 번째 조명이 있으면 그 색, 없으면 방 조명 프리셋의 림 색(조명이 하나인 방에서도 윤곽이 보이게). 조명이 캐릭터 뒤(벽 쪽)에 있으면 빛 쪽 가장자리에도 림. 벽이 빛을 막으므로 그 방 안의 조명만 셈.
- **캐릭터 그림자 = 발밑 동그란 그림자** (전투·기지, 모든 캐릭터·몬스터 — 2026-10-30). 예전 3D 실루엣 그림자(대원 모양 그림자, 움직일 때마다 3D 배경을 다시 그림)는 무거워서 뺌. 큰 몬스터(두 칸)는 넓게, 기지에서 앉으면 바닥의 발 자리, 누우면 없음. 몬스터가 불에 타면 그림자도 옅어지다 사라짐.
- 확인: `godot --path . ++ --scene=base` — 조명 원뿔 안 대원(주황)과 밖 대원(푸른 주변광)이 같은 방에서도 다르게 칠해짐.

## 전투 명중 · 회피
적에게 쓰는 **피해 · 상태 이상 스킬**은 명중 판정을 합니다 (회복·AP 부여·자기/아군 대상은 항상 맞음).
**명중률 = 스킬 명중 + 쓰는 캐릭터 명중 − 대상 회피** (5% ~ 100% 사이로 자름). 100% 면 굴리지 않음.
- 빗나가면 피해·상태 이상·넉백 모두 없음, AP 는 씀. 대상 머리 위 **`빗나감`** + 대상이 살짝 물러서는 동작, 전투 기록 `— 빗나감 (명중 n%)`.
- **기절 · 구속** 걸린 대상은 회피 0 (못 피함).
- 대상을 고를 때 노릴 수 있는 적마다 **`명중 n%`** 표시, 스킬 칸 설명에 `명중 n%`, 캐릭터 정보에 명중·회피.
- 수치 (엑셀 `data/balance.xlsx`, 시트 맨 뒤 열):
  - `캐릭터` · `몬스터` 시트 **`명중`**(%p, 기본 0) · **`회피`**(%, 0~95, 기본 0).

## 전투 상태 이상
**상태 = 이름 + 효과(규칙)**. 같은 효과를 이름만 다르게 여러 상태로 씁니다 — 예: 앨마 `진통제 투여` → 상태 `진통제`(`regen_2`), 하나 `자가 치유` → 상태 `자가 치유`(`regen_3`), 둘 다 효과 **재생**(`regen`).
**상태 id = 효과 id, 같은 효과의 두 번째부터 `_2`, `_3` …** (자동). **같은 id 는 겹치지 않음** — 다시 걸리면 하나로 남고 남은 턴·수치 큰 쪽으로 갱신. id 가 다르면 같은 효과라도 따로 걸려 둘 다 적용.
- **상태 정의 = 에디터 `스킬 트리` 탭 → `상태 정의`** (`data/statuses.json`): 상태마다 id(자동) · 이름 · **효과** · 머리 위 글자 · 색 · 설명(비우면 효과 설명). `새 상태 — 효과` 고르고 `+ 추가`(id = 그 효과의 다음 번호), `삭제`(달린 스킬에서도 뺌). 효과를 바꾸면 id 도 새 효과 번호로 바뀌고 달린 스킬도 따라감. 오른쪽 아래에 그 상태가 달린 스킬 목록(`열기`). 검사: id 가 `효과` 또는 `효과_숫자(2 이상)` 가 아니면 오류.
- **스킬에 다는 곳 = `상태 이상`** (`data/skill_status.json`): 스킬에는 상태(id)를 답니다. 수치의 뜻은 효과마다(출혈 = 최대 HP %, 넉백 = 칸 수 …).
- 게임 규칙은 효과로만 판단 (`StatusCatalog.effect_of`) → 이름을 바꾸거나 같은 효과의 새 상태를 만들어도 규칙이 그대로 적용.

스킬에 상태 이상을 달면 맞은 대상에게 확률로 걸립니다:
왼쪽 스킬 목록(전체 / 상태 이상 달린 것 / 아군이 쓰는 것 / 괴물이 쓰는 것, 달린 상태 표시) → 오른쪽에서 `+ 상태 이상 추가`, 상태·턴·수치(효과마다 뜻 표시)·확률, `빼기`. **한 스킬에 여러 개**(각각 따로 확률). 가운데에 상태 설명(이름 → 효과), 아래 검사.
`전투 테스트 플레이` = 고른 스킬을 아군 모두의 첫 스킬 칸에 넣고 첫 스테이지 전투. 스킬 자체(AP·위력·대상)는 여전히 밸런스 엑셀 `스킬` 시트.
**적용 시점**: 처음 걸릴 때 바로 한 번 + 그 캐릭터 차례가 올 때마다 **행동보다 먼저**. **n턴 = 그 캐릭터 차례 n번** (차례가 끝날 때 1 줄고 0 이면 풀림). 다시 걸리면 남은 턴·수치 중 큰 쪽.

| 상태 | 효과 (n = 상태턴, v = 상태수치) |
|---|---|
| 출혈 | 걸릴 때·차례마다 최대 HP 의 v% 피해, n턴 |
| 화상 | 걸릴 때·차례마다 **화염 속성 고정 피해** v (방어 무시), n턴 |
| 동상 | 차례 n번 뒤(그 차례 시작에) 최대 HP 의 v% 피해 1회, 그리고 풀림 |
| 감속 / 가속 | 속도 v% 감소 / 증가 → 행동 순서 (걸리면 그 라운드 남은 순서부터 다시 정렬), n턴 |
| 기절 | n턴 동안 자기 차례에 행동 불가 (AP 는 회복). **다른 아군이 자기 차례에 기절한 캐릭터와 자리를 바꾸는 것은 가능** |
| 구속 | n턴 동안 자리 이동 불가, **다른 캐릭터와 자리 교환도 불가** |
| 실명 | n턴 동안 고른 대상 대신 무작위 — 아군 대상 스킬은 아군 중 1명, 적 대상 스킬은 적 중 1명 (사거리 규칙 안에서) |
| 넉백 | 맞으면 v칸 **뒤로** 밀림 (그 칸에 같은 편이 있으면 자리를 바꿈). 맨 뒤 열·구속·부상·큰 몸집이면 안 밀림. 턴 없음(상태로 안 남음) |
| 끌어당김 | 맞으면 v칸 **앞으로** 끌려옴 (같은 편과 자리 바꿈). 맨 앞 열·구속·부상·큰 몸집이면 안 됨. 턴 없음 |
| 표식 | n턴 동안 이 대상을 노리는 공격의 위력 v% 증가(방어 빼기 전). **적 AI 는 표식이 있는 대상을 먼저 노림** (그중에서 AI 규칙대로) |
| 도발 | n턴 동안 **상대 편은 공격할 때 이 캐릭터만** 고를 수 있음 — 그 공격이 닿을 때만 (근접은 닿는 열에 있을 때). 보통 자신에게 거는 긍정 상태 |
| 취약 | n턴 동안 받는 피해 v% 증가 (출혈·화상 같은 상태 이상 피해 포함) |
| 재생 | 걸릴 때·차례마다 최대 HP 의 v% 회복 (최대 HP 까지), n턴 |
| 보호막 | 받는 피해를 v만큼 대신 막고, 다 막으면 사라짐 (상태 이상 피해 포함, 취약 반영 뒤). 최대 n턴. 상태 칸에 남은 양 표시 |

- 화면: 머리 위 배지(한 글자 + 남은 턴: `혈2`, `기1`, 동상은 터지기까지 남은 차례), 하단 상태 칸에 이름·남은 턴(마우스를 올리면 설명), 피해 숫자에 상태 이름, 걸릴 때 `출혈!`. 스킬 칸 설명에도 상태 이상 표시.
- 전투가 끝나면 전투 상태 이상은 사라짐 (기지로 넘어가는 건 부상 등 기지 상태만).
- [임시] 스킬: 강타 = 기절 1턴 50% · 측면 기습 = 출혈 2턴 10% · 고무 = 가속 2턴 30% · 소이탄(하나 액티브 북 끝) = 화상 2턴 4 · 제압 사격(이선 액티브 동 끝) = 감속 2턴 30%.
  진통제 투여(`painkiller_shot`, 지원 AP 2, 아군 1명) = 진통제(`regen_2`) 3턴 8% · 자가 치유(`self_heal`, 지원 AP 1, 자신) = 자가 치유(`regen_3`) 3턴 6% — 엑셀 스킬 시트에 추가, **아직 아무 캐릭터에게도 안 줌** (스킬 트리 에디터에서 노드로 넣기). 넉백·끌어당김·표식·도발·취약·보호막은 아직 단 스킬 없음.
  괴물(몬스터 스킬 탭에서 고침): 구울 할퀴기 = 출혈 2턴 8% · 무덤의 냉기 = 동상 2턴 20% / 늑대 발목 물기 = 구속 2턴 · 모래 차기 = 실명 1턴 70%. AI 그래프에 '그 스킬의 상태 이상이 없는 대상' 규칙 추가 (필살기 다음에 상태 이상 스킬, 다 걸려 있으면 강공격).
- 확인: `godot --path . ++ --scene=battle --battle_status=a_dan:bleed:2:10;wolf:frost:2:20` (캐릭터 id 또는 스프라이트:상태:턴:수치).

## 배경 3D + 캐릭터 2D (하이브리드, 기본)
2D 전투의 배경은 3D 방(창·문 밖 스폿라이트, 하드 섀도우, 셀 셰이더)을 2D 가상 카메라와 **같은 투영**으로 렌더한 텍스처입니다
(`BattleView3D.configure_as_background` / `set_view`, QHD 해상도로 카메라가 움직이거나 위치·프리셋이 바뀔 때만 다시 렌더).
캐릭터는 2D 스프라이트 그대로이고, 자기 위치에 실제로 닿는 빛(원뿔 범위, 창·문 개구부 통과, 문짝 가림)을 `light_probe` 로 계산해 명암을 정합니다.
- 빛 쪽 얼굴·몸을 그 광원색으로 밝히고 반대편은 셀 그림자.
- 빛이 뒤(벽의 창·문)에서 오면 **빛 쪽 가장자리에 같은 색 림**을 더함(반대 방향 마스크의 림 구역 사용). 반대편 림은 그쪽에서 실제 빛이 올 때만.
- 보이지 않는 그림자 대리 물체로 캐릭터 그림자가 바닥에 드리워집니다.
(예전 2D 배경 판과 3D 캐릭터 전투 씬은 2026-10-27 제거.) 투영 확인용 `--bgdebug=1`(슬롯 위치 빨간 점).

## 전투 카메라
전투가 시작되면 먼저 전장 전체 구도를 약 1초 보여준 뒤 2배로 줌인하고, 이후 차례가 온 캐릭터의 몸 중심을 화면 가운데
(상단 바와 하단 명령 패널 사이 중앙)로 옮깁니다. 3D 배경은 2D 카메라의 위치·줌을 그대로 따라 다시 그려서, 줌을 해도 흐려지지 않고
화면 가장자리 캐릭터도 정확히 중앙에 올 수 있습니다. 배경 밖은 보이지 않게 제한합니다. 값은 `battle_view_2d.gd` 의 `CAM_*` 상수.
스크린샷 CLI 는 기본으로 인트로를 건너뛰며 `--intro=1`(재생), `--intro=hold`(전체 구도에서 멈춤)로 바꿀 수 있습니다.

## 캐릭터 스프라이트 애니메이션 (스프라이트 시트, Skeleton2D 리그는 제거)
![전투 — 기본 그림](docs/screenshots/battle_sprites.png)

캐릭터(전투·기지 공통)는 **직접 뽑은 스프라이트 프레임**으로 움직입니다. 폴더: `assets/characters/<id>/`
(`dan` 단 · `kira` 키라 · `ethan` 이선 · `hero2` 하나 · `alma` 앨마 · `nikita_army` 니키타 · `ghoul` 구울 · `wolf` 늑대 · `slime`).
- `base.png` = 기본 한 장 (지금은 예전 리그를 쉬는 자세로 합친 원화). **애니메이션 프레임이 없는 동작은 이 그림이 그대로 서 있거나 미끄러지듯 이동**합니다.
- **스프라이트 시트 넣기 (기본 방법)**: 시트 한 장을 `assets/characters/<id>/` 에 **`<동작>_<칸 수>.png`** (한 줄) 또는 **`<동작>_<열>x<행>.png`** 이름으로 두면 끝.
  예: `assets/characters/kira/walk_8.png` (8칸 한 줄), `assets/characters/kira/attack_4x2.png` (4열 2행, 빈 칸은 건너뜀). 칸은 모두 같은 크기, 왼쪽 위부터 오른쪽으로.
  **발 위치·키는 첫 칸 그림에서 자동** (그림 맨 아래 가운데 = 발, 그림 높이 = 키 → 캐릭터 키(cm)에 맞춰 크기 조절). 칸 안에서 캐릭터가 움직이는 만큼은 그대로 움직입니다.
  속도·반복 등은 같은 이름 json(선택): `walk.json` = `{"fps": 10, "loop": true, "ground": [x, y], "figure_px": 키 픽셀, "weapon": false, "durations": [초, …]}`.
- **끊기는 프레임 고치기** (시트 그림은 그대로): json 에 `"skip": [14, 15, 16]` = 그 칸 빼기, `"order": [1, 5, 13, …]` = 그 순서로 재생 (칸 번호는 왼쪽 위부터 1),
  `"align_feet": true` = 칸마다 발바닥을 같은 땅선에 맞춤 (그림마다 발 높이가 달라 위아래로 튈 때).
  (예전 적용 예: 하나 walk `skip [14,15,16]` — 그림 교체로 시트는 지움.)
- 여러 동작을 한 장에: `sheet.png` + `sheet.json` = `{"cols": 8, "rows": 4, "anims": {"idle": {"row": 0, "count": 6, "fps": 8}, "walk": {"row": 1, "count": 8}, …}}`.
- 프레임 낱장으로도 됨: `assets/characters/<id>/<동작>/0001.png, 0002.png …` (이름 순서대로 재생, 기본 12fps).
  **캔버스 크기·발 위치를 `base.png`(512×768, 발 접지점 `character.json` 의 `ground`)와 같게** 그리면 따로 설정할 것이 없습니다.
  다르면 그 폴더에 `anim.json`: `{"fps": 12, "loop": true, "ground": [x, y], "figure_px": 정수리~발 픽셀, "hip_y": 골반 y, "weapon": false}`.
- 동작 이름: 기지 `idle`(서 있기) · `walk`(이동) · `sit`(의자·소파, 골반 높이 = `hip_y`) · `sleep`(누워 자기, 눕혀 그린 그림·접지점 = 침대에 닿는 몸 가운데) ·
  `work`(업무·치료) · `clean`(청소, 없으면 work) · `train`(훈련, 없으면 work) · `talk`(대화) / 전투 `idle` · `attack` · `hit` · `heal` · `death`(마지막 프레임 유지).
  attack·hit·heal 은 한 번 재생 후 idle. 프레임이 없으면: 앉기 → 의자 앞에 서 있음, 자기 → 기본 그림을 눕힘, 전투 동작 → 간단한 앞뒤 이동·흔들림.
- 무기: **손에 붙이는 무기 그림은 기본으로 숨김** (전투는 다키스트 던전처럼 무기까지 그려 넣은 정지 그림으로 갈 예정). 필요한 동작만 `anim.json` 에 `"weapon": true` 면 손 위치(`character.json` 의 `hand`)에 붙음.
- 조명(셀 명암) 마스크: 프레임·시트만 넣어도 동작합니다(마스크 없이 고른 조명). 방향 있는 명암을 원하면 `python3 tools/char_sprites.py masks` → 프레임·시트마다 `_mask_l/_r.png` 생성 (시트를 주시면 제가 만들어 둡니다).
- 새 프레임은 게임을 다시 켜면 바로 반영 (임포트 기다릴 필요 없음).
- (선택) 움직이는 GIF·WebP → 프레임 변환: `python3 tools/char_sprites.py import nikita_army hit 파일.webp` (조명 마스크까지 만듦).
  ※ 채팅에 올린 움직이는 이미지는 첫 장면 한 장으로만 전달되므로, 시트 한 장으로 주거나 저장소에 넣어 커밋해 주세요.
- 프레임마다 보여 줄 시간을 다르게: `anim.json` 의 `"durations": [2.4, 1.2]` (초, fps 대신).
- **AI 로 만든 시트(영상에서 뽑은 6x6 등) 다듬기**: `python3 tools/char_sprites.py report <시트>` → 튀는 프레임 후보 + 이음새가 매끄러운 반복 구간 후보 (마지막 다음 프레임 ≈ 첫 프레임 — 같은 자세가 두 번 나와 멈칫하지 않게),
  `python3 tools/char_sprites.py sheet <캐릭터> <동작> <시트> --frames 15-17,19-32 --fps 16 [--align ground|cell] [--weapon 0]` → 고른 프레임만 `<동작>/` 폴더로
  선 자세가 없는 시트(뛰기 등)는 `--ref-height <다른 시트의 선 키 px> --anchor torso` (머리 크기로 시트끼리 배율이 같은지 확인)
  (칸 경계는 그림이 가장 적은 줄로 자름 · 시트 전체를 똑바로 선 칸의 키로 크기 맞춤 · `ground` = 프레임마다 발을 접지선에 붙여 카메라 흔들림 제거, `cell` = 뛰기처럼 뜨는 높이 그대로 · 누운 자세는 캔버스 자동 확장 · 조명·선화·눈 마스크 프레임마다).
- **들어간 애니메이션**: **앨마 = 사용자 제공 AI 시트 5장 다듬음** (아래 그림):
  `idle` 25장 12fps (5~29, 이음새 매끄러운 반복·눈 깜빡임) · `walk` 16장 16fps (한 걸음 주기 13~29, 튀는 18 뺌) · `run` 12장 18fps (출발 1~7·코트 안 얼룩/다리 꼬인 22~27 빼고 8~19 한 주기, 뜀 높이 그대로) ·
  `attack` 13장 12fps (행동 시트: 고개 튀는 3 빼고, 길게 멈춘 자세는 2장마다, 끝의 그냥 서 있는 12장 뺌, 무기 그림 숨김) · `death` 20장 14fps (쓰러짐 1~20 후 누운 채 유지; 누운 채 숨쉬기 21~31·일어나기 32~36 은 안 씀).
  액션·쓰러짐 시트는 발이 땅에 붙어 있는데도 칸마다 땅선이 8~16px 오르내려(카메라 흔들림) 발 기준으로 맞춤. 확인: `--scene=battle --anim_frame=a_alma:death:19` (그 프레임에 멈춤).
  **단 = 사용자 AI 시트 3장**: `idle` 30장 12fps (5~34) · `walk` 17장 16fps (16~32 한 걸음 주기) · `run` 15장 18fps (12~26 한 주기, 선 자세가 없어 서 있기 시트 키로 크기, 뜀 높이 그대로).
  **이선 = 사용자 AI 시트 3장**: `idle` 24장 12fps (5~28, 주머니에 손) · `walk` 18장 16fps (14~31 한 걸음 주기) · `run` 19장 24fps (6~24 한 주기, 주기가 길어 24fps 로 빠르게).
  **하나 walk·run = 사용자 AI 시트 + 머리는 원화로 바꿔 붙임** (AI 가 얼굴을 뭉개서): `walk` 18장 16fps (10~27) · `run` 17장 22fps (11~27). `python3 tools/char_sprites.py head hero2 walk` — 원화에서 턱 아래까지 잘라 프레임마다 원화 머리 대표 색(머리카락·피부·모자) 영역이 가장 잘 겹치는 크기·기울기·위치에 붙이고 삐져나온 AI 머리카락·조각은 지움, 묶은 머리처럼 자른 선 아래로 늘어진 머리카락도 같이 (sheet 다음에 실행, `--cut <원화 y>` 턱 바로 아래 · `--deg` 기울기 폭).
  **해상도 유지 — AI 시트 4배 확대** (하나·니키타 walk·run): AI 시트 한 칸은 키 300px 정도라 게임 그림(키 760px)으로 그냥 키우면 흐릿함 → `tools/sr_upscale.py` (Real-ESRGAN 애니 모델, torch 필요)로 시트를 먼저 4배로 키운 뒤 `sheet` 에 넣음 (`--ref-height` 도 4배 값). 발밑 바닥 그림자·외곽선 밖 흰 테는 지움.
  **니키타 = 새 기본 그림 + 리깅 idle + AI 시트 walk·run (머리 = 원화)**: `idle` 32장 12fps (리깅, 손은 주머니) · `walk` 18장 16fps (10~27) · `run` 23장 22fps (13~35, 뜀 높이 그대로) — `sr_upscale` 4배 → `sheet --ref-height 1268`(모자 너비로 원화와 배율 맞춤) → `head nikita_army <동작> --cut 157` (run 은 `--deg 6 --scale 1-1`).
  **로한 = 리깅 idle** (`rig rohan`, 32장 12fps — 예전 숨쉬기 시트는 지움).
  **하나 = 리깅 idle** (시트가 안 뽑혀 원화 한 장으로): `python3 tools/char_sprites.py rig hero2` → `idle/` 32장 12fps — 다리·골반 고정, 몸통 숨쉬기(어깨 오르내림·가슴 살짝 넓어짐), 머리 = 목 기준 갸웃·끄덕(숨보다 조금 늦게), 팔 = 어깨 기준 흔들림(팔·몸통 빈틈으로 팔 영역, 빈틈 없는 쪽은 반대 팔 너비로). **눈 깜빡임 없음** (눈 자리를 피부로 덮는 방식이 얻어맞은 것처럼 보여 뺌 — 도구 `--blink` 로만). 조명·선화·눈 마스크도 같은 움직임.
  **키라 = 사용자 AI 시트 3장**: `idle` 36장 10fps (1→19→2 왕복 — 시트 19장 안에 매끄럽게 이어지는 반복 구간이 없어 앞뒤로 재생) · `walk` 19장 17fps (17~35 한 걸음 주기, 서 있기 키로 크기) · `run` 12장 18fps (15~26 한 주기, 뜀 높이 그대로).
  `breathe` (기본 그림으로 숨쉬기 idle 시트)는 이제 쓰는 캐릭터 없음 — 전원 리깅 또는 AI 시트.
  프레임을 지우거나 다시 만들 때 남은 `.import` 파일은 무시됨 (원본 PNG 가 있는 프레임만 읽음).
  속도는 같은 이름 json(`walk.json` 등). 조명 마스크 시트(`*_mask_r/_l.png`)는 `python3 tools/char_sprites.py masks` 로 칸마다 만듦 — 없어도 동작.

### 스프라이트 시트로 내보내기
`python3 tools/char_sprites.py export <캐릭터> [idle walk run] [--cols 6]` → `exports/sheets/<캐릭터>/<동작>_sheet.png` + `<동작>_sheet.json`.
- 프레임(`<동작>/0001.png …`, 원화 색 그대로 · 투명 배경 · 원본 해상도)을 왼쪽 위부터 가로로 6칸씩. 마스크·선화는 안 넣음.
- **모든 동작이 같은 칸 크기 · 같은 발 위치** → 동작을 바꿔도 캐릭터가 안 튐. json = 칸 크기 · 열 · 행 · 장 수 · fps · 발 위치(ground) · 발자국 프레임(steps).
- 미리보기 = `preview.jpg` (1/4 크기). `exports/` 는 Godot 가 읽지 않음(`.gdignore`).
- **동작마다 한 줄로 긴 시트 한 장**: `python3 tools/char_sprites.py rows <캐릭터> [idle walk walk:l run run:l] [--scale 1,0.5]` → `<out>/<캐릭터>/rows.png` + 절반 크기 `rows_x0.5.png` + `rows.json`.
  줄마다 동작 하나(왼쪽부터 프레임 순서, 짧은 줄 남는 칸은 투명), `:l` = 좌우로 뒤집은 왼쪽 보기(원본 = 오른쪽 보기). 칸은 발이 가운데 아래 — 뒤집어도 발 위치가 같음.
  니키타: 1줄 idle(32) · 2줄 오른쪽 걷기(18) · 3줄 왼쪽 걷기(18) · 4줄 오른쪽 뛰기(23) · 5줄 왼쪽 뛰기(23), 칸 616×804, 원본 19712×4020 (가로 16384 넘음 → 엔진에 넣을 땐 `rows_x0.5.png` 9856×2010, 칸 308×402).
- 지금 있는 것: **니키타**(`nikita_army`) idle 32장 12fps · walk 18장 16fps · run 23장 22fps, 칸 562×804, 발 (308, 797).

### 효과음 (발자국 · 쓰러짐)
- **발자국**: 캐릭터마다 걷기·뛰기 소리 (아군 6명 모두: **키라 · 니키타 · 이선 · 하나 · 앨마 · 단**). 걷기·뛰기 애니메이션에서 **발이 땅에 닿는 프레임**마다 한 걸음씩 재생 → 애니메이션 속도가 달라도 발과 소리가 맞음.
  - 기지: 대원이 걷거나 뛸 때. 전투: 자리 이동·자리 바꾸기 때 두 걸음 (전투는 멈춘 그림으로 미끄러지므로).
  - 화면 위치 소리(가운데에서 멀수록 작게, 좌우로 나뉨). 소리 파일이 없는 캐릭터는 조용함.
- **쓰러짐(dead)**: 공용 — 전투에서 아군·몬스터 누구든 쓰러질 때.
- 새 소리 넣기: `python3 tools/sfx_steps.py <캐릭터 id> walk|run <발자국.mp3> [--skip 1]` → 걸음마다 잘라 `assets/characters/<id>/sfx/walk_01.ogg …` (원본은 `assets/source/sfx/`, 다른 걸음보다 4dB 넘게 작거나 큰 조각은 크기를 맞춤).
  공용: `python3 tools/sfx_steps.py --common <이름> <소리.mp3>` → `assets/sfx/<이름>.ogg`.
  발 닿는 프레임: `python3 tools/char_sprites.py steps <캐릭터>` → anim.json `"steps"` (걷기 = 두 발이 가장 벌어진 프레임, 뛰기 = 가장 낮은 프레임 · 직접 고쳐도 됨).
- [임시] 음량: `scripts/presentation/sfx.gd` 상단 (`FOOTSTEP_DB` 0 · `DEAD_DB` -3 dB).

### 선화 유지 (조명은 면에만)
캐릭터 그림마다 **선화 마스크**(`<그림>_line.png`, `python3 tools/char_sprites.py lines`, `new` 는 자동)를 두면 셰이더가 **선은 원화 색 그대로** 두고 면에만 조명을 입힙니다.
선 = 주변보다 가늘게 어두운 획(외곽선·주름·눈·머리카락 선), 넓게 어두운 면(검은 옷)은 선이 아니라 조명을 받음. 선 옆 밝은 테두리는 조명색 유지(어두운 쪽만 원화로).

### 네온 칠 (전 캐릭터 기본)
모든 캐릭터를 **선화는 원화 그대로, 면은 조명색으로 쨍하게** 칠합니다 (레퍼런스: `docs/screenshots/ref_neon.png`).
- 원화 밝기 → 조명색 명도. 검정 옷도 바닥 밝기(`neon_floor`)까지 올라가 깊은 보라·남색이 되고, 흰 코트는 흰빛 섞인 조명색. 선은 그보다 어두운 원화 색이라 묻히지 않음.
- **외곽 림**(빛 반대쪽 가장자리의 보조광 선): 셰이더가 그림 실루엣에서 직접 그림 — 두께 `rim_px`(원화 키 760px 기준 14px), 실루엣을 따라 매끄럽게(계단 없음). 바깥이 트인 가장자리에만 생김 — 그림 안쪽 작은 틈(턱 아래·목 옆·밑단과 부츠 사이)엔 안 듦. 머리카락 끝 같은 가는 끝까지 채움(림 띠 안에서는 어두운 먹선만 선화로 남김).
- **눈은 원본 색**: 눈 마스크 `base_eye.png`(흰자·눈동자·동공)가 있으면 그 부분은 조명·네온 없이 원화 색. `python3 tools/char_sprites.py eyes <캐릭터> [x0,y0,x1,y1 …]` (상자 없으면 머리 영역에서 자동, `new` 는 자동). 지금은 시험 캐릭터만.
- `character.json` `"style": "classic"` → 예전 셀 칠. `"neon_gradient": 1` → 몸 위(빛 쪽)에서 아래로 조명 색상이 푸른 보라 쪽으로 넘어가는 그라데이션 (기본 끔).
- 실행 옵션으로 비교: `--char_style=neon|classic`, `--char_gradient=0|1` (모든 캐릭터에 강제). 세기는 셰이더 `neon_*`·`rim_px` 값.
- 기지 확대 촬영: `--base_focus=npc_nikita --base_zoom=3.6 --base_focus_y=0.9`.

## 데이터 흐름
`BattleController` 가 상태 머신(PREPARE → INITIATIVE → ROUND_START → ACTOR_START → PLAYER_COMMAND/ENEMY_AI → ACTION_RESOLVE → …)을 돌리며
신호만 내보내고, `BattleView2D`/`BattleView3D` 는 같은 `BattleViewBase` 인터페이스로 그 신호를 연출로 바꿉니다.
모든 행동은 `can_execute → pay_ap → resolve → emit_event` 한 경로(`BattleController._execute`)를 지납니다.

## 임시 에셋 주의
캐릭터/배경은 `tools/gen_sprites.py` 가 도형으로 생성한 **검증용 대체 원화**입니다. 레퍼런스 이미지는 포함하지 않았습니다.
